## 1. 系统一句话架构

```
        ┌── I2C-1 ──┬── MAX30102（0x57）心率血氧
        │           └── LCD1602 转接板（0x27/0x3F）显示
树莓派 5 ├── SPI0.0 ─── MCP3002（10 位 ADC）── TMP36（模拟体温）
（BCM2712）├── GPIO4 ─── DHT11（单总线温湿度）
        ├── GPIO17 ── HC-SR501（人体红外）
        ├── GPIO18 ── 蜂鸣器        GPIO22/23/24 ── 绿/黄/红 LED
        ├── GPIO27 ── 求救按钮
        └── 蓝牙 A2DP ── 蓝牙音箱（espeak-ng 语音播报）
```

数据流：驱动读传感器 → `core/collector.py` 轮询 → `core/rules.py` 判报警 →
`core/dispatcher.py` 下发到 LCD / 蜂鸣器 / LED / 音箱 → `net/web.py` 供手机轮询。

| 件 | 为什么需要 | 装/不装的区别 |
| --- | --- | --- |
| **10kΩ 电位器** | MCP3002 的 CH1 目前空着。想演示"ADC 能读任意模拟量"或给 TMP36 做对照实验时用它 | 不装：CH1 悬空（不影响 TMP36，TMP36 走 CH0）；装了：多一路可手动调节的模拟输入 |
| **TMP36 转接板** | 清单里的 TMP36GT9Z 若是 **SOT-23 贴片**封装，面包板插不上，必须焊到 SOT-23 转 DIP 的转接板 | 不装：根本插不进面包板；TO-92（三脚直插）封装则不需要 |
| **两个电阻（1kΩ + 2kΩ）** | 找不到 TXS0102 时，用分压替代给 HC-SR04 的 ECHO 降压 | 二选一即可，不必同时准备 TXS0102 和分压电阻 |
| **0.1µF 陶瓷电容** | 跨接 TMP36 的 +VS 与 GND（数据手册推荐），抑制电源噪声 | 不装：大多数情况也能读，但读数可能更抖 |
| **DHT11 上拉电阻 4.7k~10kΩ** | 只有**裸四针** DHT11 需要；三针成品模块已自带 | 裸传感器不加上拉 → 读数一直 NaN / 超时 |
| **5V/5A USB-C 电源** | 树莓派 5 官方要求 5V/5A（见 `03-供电与安全.md`） | 电源不足 → 掉电重启、I2C 误码、USB 设备掉线 |

## 4. 两个必须讲清楚的工作原理要点（答辩必答）

### 4.1 树莓派 5 **没有任何模拟输入引脚**

树莓派 5 的 40-pin 全是**数字**引脚：GPIO 只能读"高/低"两个电平，读不出"1.234V"
这种连续电压。所以：

- **TMP36GT9Z 是模拟输出器件**（10mV/°C），它的 VOUT **必须**先接 MCP3002 这类
  ADC 转成数字量，再经 SPI 进树莓派；
- 完整链路：`TMP36 VOUT → MCP3002 CH0 → SPI0 → 原始值 0~1023 → 电压 V → 温度 °C`；
- 换算：`V = raw/1023 × 3.3`，`T(°C) = (V − 0.75) × 100 + 25`；
- 10 位 ADC 的 1 LSB ≈ 3.23mV ≈ **0.32°C**，这是本方案的分辨率下限。

### 4.2 MAX30102 **不可能**接 MCP3002

MCP3002 是 **ADC（模数转换）**：它只接受**模拟电压**作为输入，
输出数字值给 SPI。

MAX30102 是 **I2C 数字器件**：它内部已经完成了光电转换 + ADC，对外直接给出
**数字式的 FIFO 采样值**，靠 SDA/SCL 两根线传数据。它**没有模拟输出引脚**，
所以：

- MAX30102 **只能接 I2C-1**（GPIO2=SDA 物理脚 3、GPIO3=SCL 物理脚 5）；
- 把它接到 MCP3002 的 CH0/CH1 上**在原理上就是错的**——ADC 收模拟电压，
  而 MAX30102 根本不输出电压；
- 反过来也错：把 TMP36 直接接 GPIO 读不出任何有意义的值（只能读出 0 或 1）。

一句话：**模拟器件找 ADC，数字器件找总线（I2C/SPI/UART），两者不能混接。**

## 5. LCD1602 只能显示 ASCII（必须牢记）

LCD1602 用的是 **HD44780 字库芯片，只内置 ASCII 字符**，**没有中文字库**。

- 直接下发中文 → 屏上出现随机点阵，看起来就是**花屏**；
- 本项目的 `lcd1602` 驱动已经做了保护：非 ASCII 字符一律替换成 `?`
  （`sanitize()`，可用 `non_ascii_fallback` 改），**绝不让非法字节进 I2C**；
- 因此**界面文案必须用英文/拼音缩写**。中文留给手机端和语音播报（`bt_speaker`）。

**推荐的英文显示文案（16 列 × 2 行，每行不超过 16 个字符）**：

| 场景 | 第一行 | 第二行 |
| --- | --- | --- |
| 正常 | `HR 72 SpO2 98%` | `T 36.5C OK` |
| 未贴手指 | `Place finger` | `on sensor` |
| 心率过高 | `ALARM: HR HIGH` | `HR 128 bpm` |
| 心率过低 | `ALARM: HR LOW` | `HR 42 bpm` |
| 血氧过低 | `ALARM: SpO2 LOW` | `SpO2 89%` |
| 体温过高 | `ALARM: TEMP HI` | `T 38.2C` |
| 环境温度过高 | `ALARM: ROOM HI` | `T 32.1C 65%` |
| 湿度过高 | `ALARM: HUMID` | `RH 88%` |
| 久无活动 | `ALARM: NO MOTION` | `Silent 31min` |
| 传感器故障 | `SENSOR FAULT` | `HR sensor` |
| 已消音 | `SILENCED` | `Press SOS` |
| 求救已触发 | `SOS SENT` | `Help is coming` |

⚠️ 每行都必须**补满空格**（驱动已自动 `ljust(cols)`），否则上一屏的残留字符会跟进
新文本后面（例如 `HR 72 bpmALARM`）。

## 6. 两个容易搞错的电平事实

| 器件 | 供电 | 输出电平 | 能否直连 GPIO |
| --- | --- | --- | --- |
| **HC-SR501** | **必须 5V**（物理脚 2/4）。3.3V 供电会导致误触发、探测距离变短 | **3.3V**（板载稳压+电平转换） | **可以直连**，不需要 TXS0102 |
| **HC-SR04**（拓展） | **必须 5V**（物理脚 2/4），3.3V 下工作不稳定 | **ECHO 是 5V** | **绝对不行**！必须经 TXS0102 或电阻分压（`ECHO─1kΩ─┬─GPIO27`、`┬─2kΩ─GND`） |

记忆点：**HC-SR501 是"5V 供电、3.3V 输出"，HC-SR04 是"5V 供电、5V 输出"。**
两者名字只差一位，接法完全不同——把 HC-SR04 的 ECHO 直接插 GPIO 会打坏引脚。

## 8. 接线完毕后的自检清单

按顺序做，每一步都通过再进下一步。

**① 断电检查（万用表，或至少目视）**

- [ ] 3.3V 与 GND 之间**没有短路**（面包板电源轨正负极没接反）
- [ ] 5V 引脚**没有**接到任何 3.3V 器件的 VCC（MAX30102 / DHT11 / TMP36 / MCP3002）
- [ ] 每个 LED、蜂鸣器的信号线上**都串了限流电阻**（220Ω~1kΩ）

**② 上电，确认接口已启用**

```bash
sudo raspi-config        # Interface Options → I2C → Enable；SPI → Enable
```

**③ I2C 总线**

```bash
i2cdetect -y 1
```

- [ ] 应看到 **0x57**（MAX30102）
- [ ] 应看到 **0x27 或 0x3F**（LCD1602 的 PCF8574 转接板）
- 看不到 → 查 SDA=物理脚 3 / SCL=物理脚 5 是否接反、器件 VCC 是否接对、I2C 是否启用

**④ SPI 设备节点**

```bash
ls -l /dev/spidev0.*
```

- [ ] 至少存在 `/dev/spidev0.0`（MCP3002 用 SPI0.0 = CE0 = 物理脚 24）
- [ ] 当前用户在 `spi` 组：`sudo adduser $USER spi`（之后**必须重新登录**）

**⑤ GPIO 权限**

```bash
sudo apt install -y python3-gpiozero python3-lgpio
```

- [ ] 树莓派 5 **不能用 `RPi.GPIO`**，本项目统一用 `gpiozero`（底层 `lgpio`）

**⑥ 回路电阻检查（断电状态下用万用表）**

- [ ] 每个 LED 支路：GPIO 引脚 ↔ GND 的二极管档读数应为"正向导通、反向不通"
- [ ] TMP36 的 VOUT ↔ MCP3002 的 CH0（脚 1）应**导通**（同一根线）
- [ ] TMP36 的 VOUT **不导通**到任何树莓派 GPIO（模拟线不许进 GPIO）
- [ ] 所有器件的 GND 与树莓派 GND **全部导通**（共地）

**⑦ 软件自检（mock 先跑，再接硬件跑 real）**

```bash
cd rpi
python -m pytest -q                      # 全绿说明代码链路正常
python -m health_monitor.serve --mock    # mock 模式演示，不碰硬件
python -m health_monitor.serve           # 真实模式
```

- [ ] `GET /api/v1/health` 里每个器件的 `fault_count` 为 0
- [ ] `last_error` 为 `null`
