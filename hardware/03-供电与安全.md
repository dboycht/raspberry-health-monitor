# 03 · 供电与安全

> 本文档回答：**电从哪来、够不够用、电平对不对、哪个地方会把板子烧了。**
>
> ⚠️ **本文所有电流数值都是"估算值，未实测"** —— 本项目至今没有在真实树莓派 5
> 上接过传感器，也没有用电流表量过任何一路电流。数据取自器件数据手册的典型值，
> 与实际（尤其廉价模块）可能有明显偏差。
> **本文的引脚号与电平判断为纸面推导，未实测。**

---

## 1. 树莓派 5 自身的供电要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 官方电源 | **5V / 5A（27W）USB-C PD** | 树莓派 5 的官方推荐规格 |
| 最低可用 | 5V / 3A（15W） | 能跑起来，但 USB 外设受限、高负载会掉电重启 |
| 接口 | USB-C，**支持 PD 协议的电源** | 普通 5V/2A 手机充电器**不够** |
| 欠压阈值 | 约 4.63V | 低于此值系统会在内核日志报 `Under-voltage detected` |

**树莓派 5 的 USB 口默认限流**：官方 27W 电源下，USB 口合计可提供约 **1.6A**；
若电源不是 PD 或功率不足，USB 限流会降到 **600mA**，外接设备会掉线。

**检查供电是否足够**：

```bash
vcgencmd get_throttled        # 返回 0x0 = 正常
# 非 0 的常见位：0x1=欠压 0x2=ARM 降频 0x4=当前降频 0x10000=曾欠压
vcgencmd measure_volts        # 看核心电压
dmesg | grep -i voltage       # 看内核有没有报欠压
```

**常见坑**：

- 用手机充电器（5V/2A）→ 一开蜂鸣器 + LCD 背光就掉电重启（**最典型的"接线没错却跑不稳"**）
- 用劣质 USB-C 线（线芯细、压降大）→ 同样欠压，**换电源前先换线**
- 5V 引脚（物理脚 2/4）与 3.3V 引脚（1/17）**短接** → 立刻烧 3.3V 稳压电路

## 2. 供电预算（估算值，未实测）

### 2.1 器件电流估算表

| 器件 | 供电轨 | 典型电流 | 峰值电流 | 备注 |
| --- | --- | ---: | ---: | --- |
| **树莓派 5 本体** | 5V | 600mA（空闲） | **5000mA（满载 5A）** | 官方 27W 电源规格 |
| MAX30102 | 3.3V | ~1.2mA（待机） | ~20mA（两个 LED 同时点亮时） | LED 电流配置 7.6mA/个 |
| DHT11 | 3.3V | ~0.5mA | ~1.5mA（测量瞬间） | 测量时才有较高电流 |
| TMP36 | 3.3V | ~0.05mA | 0.05mA | 静态电流极低 |
| MCP3002 | 3.3V | ~0.4mA | ~1mA | 转换时 |
| **LCD1602（含背光）** | **5V** | ~20mA | ~30mA | **背光是主要耗电者** |
| **HC-SR501（PIR）** | **5V** | ~0.05mA（平均） | ~1mA | 平均功耗很低 |
| 有源蜂鸣器 | 3.3V（经电阻） | ~7mA | ~15mA | 由 GPIO 驱动，受电阻限制 |
| LED × 3（绿/黄/红） | 3.3V（经电阻） | 每个 ~5~8mA | 每个 ~10mA | **任意时刻只亮一个**（驱动保证） |
| HC-SR04（拓展，默认关闭） | 5V | ~2mA | ~15mA（测距瞬间） | 默认不启用 |
| 蓝牙音箱 | **自供电** | 0（不由树莓派供电） | 0 | **不要从树莓派 5V 脚给音箱供电** |
| 树莓派板载蓝牙 | 3.3V | ~30mA | ~50mA | 蓝牙适配器工作时的额外消耗 |

### 2.2 分轨汇总

| 供电轨 | 谁来供 | 合计典型 | 合计峰值 | 结论 |
| --- | --- | ---: | ---: | --- |
| **5V 轨（器件侧）** | 树莓派物理脚 2/4 | **~22mA** | **~46mA** | LCD1602 + PIR（拓展再 +15mA） |
| **3.3V 轨（器件侧）** | 树莓派物理脚 1/17 | **~25mA** | **~60mA** | 全部 3.3V 器件合计 |
| **5V 输入（整机）** | USB-C 电源 | ~650mA | **~5000mA** | 器件侧占比极小，**瓶颈是树莓派自己** |

### 2.3 结论

1. **器件侧的耗电可以忽略**：本项目外接器件合计典型电流只有 ~50mA，
   峰值不到 110mA。**真正吃电的是树莓派本体**（空闲 600mA、满载可达 5A）。
2. **电源选型**：直接用**官方 5V/5A（27W）USB-C PD 电源**。
   不要用手机充电器，不要用电脑 USB 口（500mA~900mA，必然欠压）。
3. **3.3V 轨的余量**：树莓派 3.3V 轨（物理脚 1/17）的可用电流有限
   （通常建议**不超过 ~500mA**，且与板载外设共用）。
   本项目器件侧只用 ~25mA，**余量非常充足**。
   ⚠️ 但**绝不要**从 3.3V 脚给舵机、电机、WS2812 灯带这类大电流器件供电。
4. **不要从树莓派给蓝牙音箱供电** —— 音箱自带电池/独立电源，
   从树莓派 5V 脚接音箱会瞬间拉爆电源或烧走线。

⚠️ **以上全部为估算值，未实测。** 报告里请如实标注，
若要做功耗数据，请用 USB 电流表（USB-C 功率计）实测整机电流。

## 3. 电平匹配

### 3.1 电平总则

| 方向 | 电平 | 能否直连树莓派 GPIO |
| --- | --- | --- |
| 3.3V 器件输出 → GPIO 输入 | 3.3V | ✅ 可以 |
| 5V 器件输出 → GPIO 输入 | 5V | ❌ **绝对不行**，必须先降到 3.3V |
| GPIO 输出（3.3V）→ 3.3V 器件输入 | 3.3V | ✅ 可以 |
| GPIO 输出（3.3V）→ 5V 器件输入 | 3.3V | ⚠️ 多数情况"够用"（很多 5V 器件的高电平阈值只有 2.0V），但**不保证** |

**树莓派 GPIO 不是 5V 容限（not 5V-tolerant）**。
把 5V 直接灌进任何一个 GPIO 都可能永久损坏该引脚。

### 3.2 本项目逐个器件的电平判定

| 器件 | 供电 | 输出电平 | 是否需要电平转换 | 判定依据 |
| --- | --- | --- | --- | --- |
| MAX30102 | 3.3V | I2C 3.3V 开漏 | **不需要** | 与 GPIO 同为 3.3V |
| DHT11 | 3.3V | 单总线 3.3V | **不需要** | 3.3V 供电时数据电平也是 3.3V |
| TMP36 | 3.3V | **模拟电压 0.1~1.75V** | **不需要（但必须经 ADC）** | 走 MCP3002，不进 GPIO |
| MCP3002 | 3.3V | SPI 3.3V | **不需要** | VDD/VREF 都是 3.3V |
| LCD1602 转接板 | 5V | I2C 开漏，被总线上拉到 3.3V | **不需要** | PCF8574 的 I2C 引脚是开漏输出，**高电平由总线上拉电阻决定**，上拉到 3.3V 就不会灌 5V 进 GPIO |
| **HC-SR501** | **5V** | **3.3V**（板载稳压 + 电平转换） | **不需要** | 这是模块设计的优点，**与 HC-SR04 不同** |
| 蜂鸣器 | 3.3V 驱动 | — | **不需要** | 纯输出 |
| LED | 3.3V 驱动 | — | **不需要** | 纯输出 |
| 按钮 | 无源 | 被内部上拉到 3.3V | **不需要** | 按下接地 |
| **HC-SR04（拓展）** | **5V** | **ECHO = 5V** | **必须！** TXS0102 或 1kΩ+2kΩ 分压 | 5V 直连 GPIO 会烧引脚 |
| 蓝牙音箱 | 自供电 | 蓝牙无线 | **不涉及** | 无电气连接 |

### 3.3 HC-SR501 vs HC-SR04：一字之差，接法完全不同

| | HC-SR501（人体红外） | HC-SR04（超声波） |
| --- | --- | --- |
| 供电 | **5V**（物理脚 2/4） | **5V**（物理脚 2/4） |
| 输出电平 | **3.3V** | **5V（ECHO）** |
| 直连 GPIO | ✅ **可以** | ❌ **绝对不行** |
| 原因 | 板载 3.3V 稳压 + 电平转换 | ECHO 直接是 5V 推挽输出 |

**记忆口诀：SR501 是"5V 供电、3.3V 说话"；SR04 是"5V 供电、5V 说话"。**

⚠️ **未实测的边界情况**：市面上部分 HC-SR501 廉价仿制板可能不做电平转换，
OUT 在 5V 供电时**可能**输出接近 5V。稳妥做法是**上电后用万用表量一次 OUT 对 GND 的电压**：
若是 5V，就必须加电平转换（同 HC-SR04 的处理方式）。**本项目未做这个测量。**

## 4. 保护电阻

### 4.1 限流电阻计算（LED）

公式：`R = (Vcc − Vf) / I`

- `Vcc = 3.3V`（树莓派 GPIO 输出高电平）
- `Vf` = LED 正向压降（红 ≈ 2.0V，绿/黄 ≈ 2.1~2.2V，蓝/白 ≈ 3.0~3.2V）
- `I` = 目标电流（LED 指示用 **5~10mA** 足够亮）

| LED 颜色 | Vf 估算 | 目标电流 | 理论电阻 | **本项目建议** | 实际电流 |
| --- | ---: | ---: | ---: | --- | ---: |
| 红 | 2.0V | 10mA | 130Ω | **220Ω** | ≈ 5.9mA |
| 黄 | 2.1V | 10mA | 120Ω | **220Ω** | ≈ 5.5mA |
| 绿 | 2.2V | 10mA | 110Ω | **220Ω** | ≈ 5.0mA |

**取值建议：220Ω ~ 1kΩ 都安全。**

- 220Ω → 约 5~6mA，够亮、对 GPIO 友好
- 1kΩ → 约 1~1.3mA，偏暗但**最安全**（电池/长导线场景可选）
- **不要小于 100Ω**：电流会超过 GPIO 推荐值，也接近 LED 上限

⚠️ **蓝色/白色 LED 注意**：Vf 高达 3.0~3.2V，接 3.3V 时压差太小，
电流极不稳定（甚至不亮或过流）。若要用蓝色 LED，建议串 **100~150Ω** 并实测电流，
或改用 5V 供电（此时必须自己算电阻，**不能让 5V 直接进 GPIO**——
需要用三极管/MOSFET 驱动）。

### 4.2 蜂鸣器限流电阻

| 项目 | 值 |
| --- | --- |
| 树莓派单脚推荐电流上限 | **16mA**（BCM2712） |
| 蜂鸣器直流电阻 | 很小（几十 Ω 量级） |
| **必须串的电阻** | **220Ω ~ 1kΩ** |
| 建议取值 | **220Ω**（约 5mA~10mA，声音够响） |

⚠️ **不串电阻直接接 GPIO = 烧引脚**。这是本项目第二常见的烧板原因。

### 4.3 上拉 / 分压电阻清单

| 用途 | 阻值 | 接法 | 是否必需 |
| --- | --- | --- | --- |
| DHT11 数据上拉（**仅裸四针**） | **4.7kΩ ~ 10kΩ** | DATA ↔ 3.3V | **必需**（三针模块已自带） |
| 按钮上拉 | 无（用内部上拉） | — | 不需要 |
| I2C 总线（SDA/SCL）上拉 | 模块自带 | 上拉到 3.3V | 不需要另加；**总等效上拉不宜小于 1kΩ** |
| TXS0102 的 OE 使能上拉 | **10kΩ** | OE ↔ VCCA(3.3V) | 用 TXS0102 时必需 |
| HC-SR04 ECHO 分压 | **1kΩ + 2kΩ** | `ECHO─1kΩ─┬─GPIO6`、`┬─2kΩ─GND` | 不用 TXS0102 时必需 |
| TMP36 去耦电容 | **0.1µF**（不是电阻） | 跨接 +VS 与 GND | 数据手册推荐 |

分压验算（方案 B）：`5V × 2kΩ / (1kΩ + 2kΩ) = 3.33V`，
落在 3.3V 安全范围内（略高 0.03V 可忽略）。
⚠️ **换成别的阻值必须重新算**，例如 1kΩ+1kΩ 会得到 2.5V（可能被判定为低电平）。

## 5. 常见烧板风险（按危险程度排序）

### 风险 1：5V 接到 3.3V 器件的 VCC（最高频、最贵）

| 受害器件 | 后果 |
| --- | --- |
| **MAX30102** | **烧芯片**（最贵的器件） |
| **DHT11** | 数据电平被拉到 5V，伤 GPIO |
| **TMP36** | 输出超 ADC 量程，读 1023，可能损坏 ADC 输入 |
| **MCP3002** | 量程变为 0~5V，读数错误，有损坏风险 |

**防呆做法**：
- 红色线（3.3V）与橙色线（5V）**严格分开**，面包板两条正电源轨不短接
- 插线前逐根核对"这根线的另一端在哪条轨上"
- 上电前用万用表量每个 3.3V 器件的 VCC 脚对 GND，**必须是 3.3V**

### 风险 2：HC-SR04 的 ECHO 直连 GPIO

- **后果**：5V 灌进 GPIO，**永久损坏该引脚**（甚至整块板）
- **必须**：TXS0102 或 1kΩ+2kΩ 分压
- **注意**：这个问题只在启用拓展件 HC-SR04 时出现；核心链路里没有 5V 输出接 GPIO

### 风险 3：LED / 蜂鸣器不串限流电阻

- **后果**：电流超过 GPIO 16mA 推荐上限，长期运行烧引脚
- **必须**：每个 LED、蜂鸣器信号线上各串一个 220Ω~1kΩ

### 风险 4：5V 与 3.3V 引脚短接

- **后果**：3.3V 稳压电路被 5V 反灌，**立刻烧**
- **场景**：面包板两条正轨不小心用一根线连起来；杜邦线插错一格
- **防呆**：两条正轨用不同颜色；**上电前用万用表通断档确认两轨不导通**

### 风险 5：LED 正负极接反 / 5V 直驱 LED

- 正负极接反 → 不亮（一般不会烧，翻过来即可）
- **5V 直驱 LED（不串电阻）→ 立刻烧 LED**
- LED 必须走 **3.3V + 限流电阻**

### 风险 6：带电插拔杜邦线

- **后果**：插拔瞬间短路或浪涌，可能烧器件或 GPIO
- **纪律**：**任何接线改动都先断电**（拔 USB-C）

### 风险 7：电源功率不足导致的"假故障"

这不会烧板，但极难排查，因为**现象看起来像接线错误**：

| 现象 | 真实原因 |
| --- | --- |
| `i2cdetect` 时有时无 | 电压不稳，I2C 误码 |
| 蜂鸣器一响就重启 | 电源功率不足，瞬间欠压 |
| 程序跑一会儿卡死 | CPU 降频 / 欠压保护 |
| USB 蓝牙适配器掉线 | USB 口限流 |

**排查**：`vcgencmd get_throttled` 返回非 0 就是电源问题，**换电源或换线**。

### 风险 8：3.3V 轨超载

- 树莓派 3.3V 轨可用电流有限（通常建议不超过 ~500mA）
- 本项目器件侧只用 ~25mA，**没问题**
- ⚠️ 但**绝不要**从 3.3V 脚接舵机、直流电机、WS2812 灯带 —— 它们必须独立供电并共地

### 风险 9：上电热身期的"假报警"

不是烧板，但会让人以为硬件坏了：

- **HC-SR501 上电后约 1 分钟**才稳定，期间 OUT 会随机跳高
  → 驱动的 `settle_s` 默认只挡 1.0s，**真实部署建议传 `settle_s=60`**
- **TMP36 上电后**读数可能短暂漂移，等几秒再判越界

### 风险 10：静电（ESD）

- 干燥季节用手直接摸 MAX30102 的芯片裸露面 → 可能打坏
- **做法**：拿板子前先摸一下金属接地物（如暖气片/机箱）

## 6. 上电前的最终检查（照着做，能挡掉 90% 的烧板）

**断电状态下（拔掉 USB-C）：**

- [ ] 万用表通断档：3.3V 轨与 5V 轨**不导通**
- [ ] 万用表通断档：3.3V 轨与 GND **不导通**，5V 轨与 GND **不导通**（无短路）
- [ ] 万用表通断档：所有器件的 GND 与树莓派 GND **全部导通**（共地）
- [ ] 目视：每个 LED、蜂鸣器的信号线上**都有电阻**
- [ ] 目视：每个 3.3V 器件的 VCC 线都接在**红色轨**（不是橙色 5V 轨）
- [ ] 目视：LCD1602 与 HC-SR501 的 VCC 接在**橙色轨**（5V）
- [ ] 目视：MAX30102 的 VIN **没有**接到 5V
- [ ] 若启用 HC-SR04：ECHO 线上**有 TXS0102 或两个分压电阻**
- [ ] TMP36 的 VOUT 接的是 MCP3002 的 CH0（脚 1），**没有**接任何树莓派 GPIO

**上电后（先别急着跑程序）：**

- [ ] 用手背轻触各器件，**没有发烫**（MAX30102 微温正常，发烫立刻断电）
- [ ] `vcgencmd get_throttled` 返回 `0x0`
- [ ] `i2cdetect -y 1` 看到 0x57 与 0x27/0x3F
- [ ] `ls -l /dev/spidev0.*` 存在 `/dev/spidev0.0`
- [ ] 若装了 HC-SR501：**先等约 1 分钟**再开始判"久无活动"

## 7. 需要额外购买 / 可能缺少的件（汇总）

| 件 | 用途 | 缺了会怎样 | 替代方案 |
| --- | --- | --- | --- |
| **10kΩ 电位器** | MCP3002 的 CH1 模拟通道备用（演示 ADC / 光敏电阻） | CH1 空着，不影响 TMP36（TMP36 走 CH0） | 不装也行，CH1 悬空 |
| **TMP36 转接板（SOT-23 → DIP）** | 若 TMP36 是裸 SOT-23 贴片封装，插不进面包板 | **无法接线**（贴片焊不上杜邦线） | 无（必须买）；若手头是 TO-92 三脚直插则不需要 |
| **TXS0102** | HC-SR04 的 ECHO 电平转换 | 启用 HC-SR04 时**不能直连**（会烧引脚） | **1kΩ + 2kΩ 电阻分压**替代 |
| **4.7k~10kΩ 上拉电阻** | 裸四针 DHT11 | 读数一直 NaN / 超时 | 三针成品模块已自带，不需要 |
| **0.1µF 陶瓷电容** | TMP36 电源去耦 | 一般也能读，但噪声更大 | 可不装 |
| **220Ω~1kΩ 电阻 ≥4 个** | 3 个 LED + 1 个蜂鸣器限流 | **不能接**（直连会烧 GPIO） | 无（必须） |
| **5V/5A USB-C PD 电源** | 树莓派 5 官方规格 | 掉电重启、I2C 误码、USB 掉线 | 5V/3A 可勉强用，但会降频/受限 |
| **USB-C 功率计**（可选） | 实测整机功耗，把"估算"变成"实测" | 报告里只能写估算值 | 无（有万用表也行，但要串在供电回路里） |

## 8. 把"估算"变成"实测"（建议后续补做）

本项目目前**所有硬件数值都是纸面推导**。若要让报告里的数据可信，建议补做：

| 要测的量 | 工具 | 怎么测 |
| --- | --- | --- |
| 整机电流 | USB-C 功率计 | 串在电源与树莓派之间，分别记录空闲 / 满载 / 蜂鸣器响时 |
| 各器件 VCC 电压 | 万用表 | 各器件供电脚对 GND，确认是 3.3V 或 5V |
| HC-SR501 OUT 电平 | 万用表 | 5V 供电时量 OUT 对 GND，确认是 3.3V（若不是必须加转换） |
| TMP36 输出 | 万用表 | 量 VOUT 对 GND，室温下应约 0.75V；与 ADC 读数对照标定 |
| LED 支路电流 | 万用表（电流档，串入） | 确认在 5~10mA |
| 真实 I2C 地址 | `i2cdetect -y 1` | 确认 0x57 与转接板实际地址 |
| 真实传感器读数 | 程序 | 用 `python -m health_monitor.serve` 看 `/api/v1/current` |

测到实际值后，请把本文档的"估算值，未实测"改成实测值并注明测量条件
（电源型号、环境温度、测量仪器）。
