# 05 · 排错手册（按"你看到的现象"查）

> 用法：**直接搜现象**（Ctrl+F 复制报错里的一小段），或用目录跳到最接近的一节。
> 每节结构固定：**现象 → 最可能的原因（按概率排序）→ 怎么确认 → 怎么修**。
>
> 三条通用纪律先记住：
> 1. **先分层**：报错是"硬件层 / 服务层 / 云端层"哪一层？（本项目每一层都有独立的体检命令）
> 2. **先看项目自己的错误信息**：我们把排查线索**写进了异常文案**（例如会提示你跑 `i2cdetect -y 1`）。
> 3. **改一个变量一次**：同时改三处，出问题时不知道是谁的功劳。

## A. 上机 / 系统

### A1. `i2cdetect: command not found`
```bash
sudo apt update && sudo apt install -y i2c-tools
```

### A2. `/dev/i2c-1` 不存在
**原因**：I2C 没开。
```bash
sudo raspi-config    # 3 Interface Options → I5 I2C → Enable → Finish
sudo reboot
ls -l /dev/i2c-1    # 应出现
```

### A3. `/dev/spidev0.0` 不存在
同上，开 **SPI**（`I4 SPI`）后重启。

### A4. `date` 显示的时间不对（差 8 小时）
**影响**：会连累"夜间频繁起夜"规则（按本地钟点判断）与上报时间戳。
```bash
sudo raspi-config    # 5 Localisation Options → L2 Timezone → Asia/Shanghai
sudo reboot
date                 # 复核
```

### A5. `pip3 install` 报 `externally-managed-environment`
树莓派 OS 新版限制直接装 pip 包：
```bash
pip3 install --break-system-packages paho-mqtt
# 或优先用系统包：sudo apt install -y python3-paho-mqtt（若有该包）
```

### A6. `git clone` 卡住 / 超时
**判据**：`ping github.com` 丢包或 DNS 解析异常。
- 让管理员**开加速器**（Steam++/Watt Toolkit）后重试；
- 或**不用 git**：在电脑上下载仓库 ZIP，解压后把整个 `raspberry-health-monitor` 目录
  拷到树莓派的 `~` 下（本项目运行不需要 git）。

### A7. 树莓派随机重启 / 掉 WiFi
**原因**：供电不足（最常见）。
- 换 **5V/5A USB-C PD 电源**；不要用电脑 USB 口或手机充电头凑合；
- 检查 `/boot/firmware/config.txt` 无关改动；`vcgencmd get_throttled` 若返回非 `0x0` 说明发生过欠压。

## B. I2C 器件（MAX30102 / LCD）

### B1. `i2cdetect -y 1` 一个地址都没有
**原因（按概率）**：
1. **没共地**（最常见）——所有器件的 GND 都要连到树莓派；
2. SDA/SCL 接反（SDA→物理脚 3/GPIO2，SCL→物理脚 5/GPIO3）；
3. I2C 没开（见 A2）；
4. 线太长/接触不良。

**确认**：单独只接一个器件再扫（排除总线冲突）。
```bash
i2cdetect -y 1     # 只接 MAX30102 时应看到 0x57
```

### B2. 有 `0x27` 没有 `0x57`（LCD 在、心率模块不在）
**原因**：MAX30102 供电问题或模块损坏。
- 确认 `VIN` 接的是 **3.3V**（脚 1/17），`GND` 共地；
- 有些模块 `VIN` 必须接 5V 才工作——**先查你模块的丝印/商品页**；若模块 I2C 上拉接在 VIN 上，
  接 5V 会把 SDA/SCL 也拉到 5V，**可能损坏树莓派**（这种情况请加电平转换）。
- 换一根杜邦线、换一个模块试。

### B3. LCD 全黑 / 只有背光没有字
**原因**：
1. **对比度没调**：转接板背面有个蓝色电位器，用小螺丝刀慢慢转（这是最常见的"以为坏了"）；
2. 供电电压：有的转接板要 5V（脚 2），有的 3.3V 也行——两种都试；
3. 地址不是 0x27（可能是 0x3F）：本项目驱动会**自动探测** 0x27/0x3F/0x20/0x38，
   也可以在配置里显式写 `"address": 63`（0x3F）。

### B4. LCD 显示乱码 / 花屏
**原因**：① 初始化时序被干扰（线太长）；② 送进了非 ASCII 字节。
本项目驱动会把非 ASCII 降级为 `?`——**如果你看到的是中文乱码，说明用的是别人改过的版本**。
> 📌 **LCD1602 只有 ASCII 字库，显示不了中文**。界面文案请用英文（`HR 72 bpm`、`ALARM: HR HIGH`），
> 中文留给手机端与语音播报。

### B5. 心率/血氧一直是 `--`
**原因（按概率）**：
1. 手指没**完全盖住**传感器窗口（要盖住那个小黑窗，别按在边上）；
2. 手指在动 / 环境强光（用手遮一下光）；
3. 采样时间不足：算法需要约 5 秒连续采样，**刚启动等 5~10 秒**；
4. 模块没被识别（先看 B2）。

**确认**：看 `/api/v1/current` 里的 `finger_detected`：`false` 说明没贴合。

### B6. 血氧数值明显不合理（比如 80 多）
**说明**：本项目的血氧用**经验公式 `SpO2 = 104 - 17R`**，**没有与标准血氧仪标定**。
只要趋势对、量级对（95~100 正常）即可，**不要在报告里声称它是医用精度**。

## C. SPI / 模拟量（MCP3002 / TMP36）

### C1. 体温恒为 `0` 或恒为 `1023`（ADC 饱和）
**原因（按概率）**：
1. **TMP36 接了 5V**（输出超过 3.3V 参考 ⇒ 饱和 1023）⇒ 改接 3.3V；
2. GND 没接 / VOUT 没接到 MCP3002 的 CH0；
3. CS（片选）没接对：默认用 **SPI0_CE0 = 物理脚 24**；
4. **SPI 控制字位序不对**（本项目已按数据手册实现单端 CH0 = `0x68`、CH1 = `0x78`；
   真机若恒 0/1023，第一个要怀疑这里，见 `手册/03-器件任务书.md` §2.1）。

**确认**：
```bash
python3 -c "
import sys; sys.path.insert(0,'.')
from health_monitor.hal import create_device
d = create_device('tmp36', mock=False); d.open()
print(d.describe())
for _ in range(3): print(d.read())
"
```
看 `raw_adc` 与 `voltage_v`：正常体温时 raw 约 200~300。

### C2. 体温读数偏低/偏高几度
**原因**：TMP36 个体误差 + 未标定。
**修**：用冰水（0°C）与室温（用另一支温度计对照）两点求偏差，写进配置：
```json
"params": { "calibration_offset_c": -0.8 }
```

### C3. `未安装 spidev`
```bash
sudo apt install -y python3-spidev
```

## D. GPIO 器件（DHT11 / PIR / 按键 / 蜂鸣器 / LED）

### D1. `未安装 gpiozero`（树莓派上）
```bash
sudo apt install -y python3-gpiozero python3-lgpio
```
> ⚠️ **树莓派 5 上 `RPi.GPIO` 不可用**（GPIO 架构变了）。本项目统一用 `gpiozero`（底层 `lgpio`）。

### D2. DHT11 一直返回"缓存值"
**原因**：DHT11 硬件限制——**两次读取间隔必须 ≥2 秒**，读太快会拿到旧值甚至读失败。
**确认**：配置里该设备的 `read_interval_s` 应 ≥ 2.0（默认 3.0）。
**修**：把 `read_interval_s` 调到 3 秒以上；或换 DHT22（精度更高、间隔可短些）。

### D3. HC-SR501 一直 `idle`（检测不到人）
**原因（按概率）**：
1. 上电后需要**约 1 分钟**稳定（我们的驱动有 `settle_s` 忽略这段时间）；
2. **VCC 接了 3.3V** ⇒ 必须 **5V（脚 2）**；
3. 模块上两个电位器：一个调灵敏度、一个调延时，逆时针/顺时针试；
4. 走得太远/穿着厚衣服（红外探测靠温差）。

### D4. HC-SR501 一直 `detected`（人或没人都是有人）
- 延时电位器调得太长（人走后 OUT 会保持高电平一段时间，属正常）；
- 旁边有热源/阳光直射/空调出风口；
- 模块的**可重复触发/单次触发**跳线选错。

### D5. 按键"没按也一直在触发"
**原因**：你的按键模块**自带上拉**，而驱动默认启用内部上拉，两者打架。
**修**：配置里把 `pull_up` 改成 `false`：
```json
"params": { "pin": 27, "pull_up": false }
```

### D6. 蜂鸣器不响
1. **有源 vs 无源**：本项目按**有源**（给高电平就响）实现；无源需要 PWM，换有源或改驱动；
2. 正负极接反（长脚正极 → GPIO18，短脚 → GND）；
3. 没串限流电阻导致 GPIO 保护/损坏（**必须串 220Ω~1kΩ**）；
4. 用 `--quiet` 启动过（不发声）。

### D7. LED 只亮一种颜色 / 颜色不对
- **共阴/共阳**：共阴（负极接 GND）用默认配置；共阳（正极接 3.3V）要把 `active_low` 设 `true`；
- 每个 LED 都要**串限流电阻**（220Ω~1kΩ）；
- 确认三种颜色的 GPIO 没插错（绿=GPIO22/脚15、黄=GPIO23/脚16、红=GPIO24/脚18）。

### D8. PIR 一动就触发"紧急求助"
**这是撞脚**：按键与 PIR 用了同一个 GPIO。
```bash
cd rpi && python3 scripts/validate.py    # 看"引脚冲突"这一项
```
按报告改配置（本项目默认：PIR = GPIO17 / 按键 = GPIO27）。

## E. 服务与 HTTP

### E1. 启动报"端口被占用"
```
❌ 端口 8080 无法绑定：...
```
**原因**：已经有一个实例在跑（最常见），或别的程序占了端口。
```bash
pgrep -af health_monitor        # 看有没有旧进程
sudo ss -tlnp | grep 8080      # 看谁占了（需要 sudo）
```
**修**：`kill <PID>`（只杀这个）或换端口 `--port 8081`。
> ⚠️ 不要 `killall python3`（可能杀掉别的项目）。

### E2. 浏览器打不开状态页，但 `curl` 能通
- 电脑/手机与树莓派**不在同一网段**（手机用了流量？）；
- 树莓派防火墙（默认没有）；
- 用了 `--host 127.0.0.1`（只允许本机访问）⇒ 用默认 `0.0.0.0`。

### E3. 页面显示一堆"未知"
**不是 bug**，是**设计**：读不到就显示"未知"，绝不显示 0（0 bpm 会被判成"心率过低"误报）。
要查"为什么读不到"⇒ 看页面上"设备状态"表里的**最后错误**那一列，或 `/api/v1/health`。

### E4. 手机能看到数据，但数据是几秒前的
正常：轮询周期 4~5 秒 + 采集周期（体温 2 秒、DHT11 3 秒）。
若**明显超期**：看 `data_stale` 字段——为 `true` 说明树莓派那边采集停了（去查传感器）。

### E5. 服务跑一会儿自己停了
```bash
journalctl -u health-monitor -n 50 --no-pager    # 用 systemd 启动时的日志
# 或前台启动观察：
python3 -m health_monitor serve --real
```
常见原因：被 `Ctrl+C`、OOM（内存不足，极少）、GPIO 被别的进程占用。

## F. 手机 App

### F1. 报 `CLEARTEXT communication ... not permitted`
**原因**：Android 9+ 默认禁止明文 HTTP。
**修**：装的是**本项目提供的 APK**（已配好 `network_security_config.xml`）；
若你自己重新构建，确认 `AndroidManifest.xml` 里配了该文件。

### F2. 一直"连接中…"
按三层查（网络 → 服务 → 采集），命令见 `03-运行与联调.md` §5.4。

### F3. 数据都是 `--`
树莓派那边没采到（看 `/api/v1/health` 的 `devices.*.stale`）。
**不是 App 的问题。**

### F4. 长按"求助"没反应
- 长按**必须满 1.5 秒**；中途松手会取消（防误触）；
- 服务端 `--quiet` 模式下不会响铃，但接口仍会返回成功（看手机是否有"已发送"提示）。

### F5. 装不上 APK
- 手机设置里允许"未知来源"；
- 若提示签名冲突（装过同包名旧版）：先卸载旧版。

## G. OneNET 上云

### G1. 日志里完全没有 OneNET
- 配置 `onenet.enabled` 还是 `false`；
- 或没装 `paho-mqtt`：`pip3 install --break-system-packages paho-mqtt`；
- 或配置解析失败：看 `status()` 里的 `cloud.warning` 与 `mqtt.reason`。

### G2. `OneNET 连接被拒绝 rc=4`
用户名或密码不对：`product_id` 填错，或 token 里的 `res` 用错。
```bash
python3 scripts/onenet_token.py --pid <产品ID> --device <设备名> --key "<设备密钥>"
```
对照输出的 `clientId / username / password` 三项。

### G3. `rc=5 未授权`
**八成用了"产品 APIKey"而不是"设备密钥"**。
`res` 必须是 `products/{产品ID}/devices/{设备名}`，密钥必须是**设备详情页**里那串。

### G4. 控制台看不到数据流
- 设备是否显示"在线"？离线 ⇒ 连接就没成功；
- 看有没有 `rejected` 回执（日志里 `OneNET 拒绝了本次数据点`）；
- payload 必须是 `{"id":..,"dp":{流名:[{v,t}]}}`（本项目已按文档生成，可用
  `python3 -c "import json;from health_monitor.net.onenet import OneNetPublisher as P;print(json.dumps(P.build_datapoint(1,{'t':30}),ensure_ascii=False))"` 复核）。

### G5. 规则引擎不推送
1. **规则没启用**（最常见）；
2. 推送 URL 从公网不可达（先在树莓派上 `curl` 那条 URL）；
3. 规则的消息源选错了（要选 **设备数据点消息 deviceDatapoint**）。

### G6. 推送过来了但解析不了
**设计如此**：接收端点"宽容接收、先记录"，不会因为格式差异失败。
先看日志里的真实报文，再在 `Runtime.record_cloud_push` 里加字段映射。
（官方文档给的 `sysProperty`/`appProperty`/`body` 结构**尚未实测**。）

### G7. token 过期被断开
本项目在启动时现签 token（默认 24 小时）。长期运行有两种做法：
- 把 `token_ttl_s` 调大（如 `2592000` = 30 天）；
- 或用 systemd 定时重启：`systemctl edit health-monitor` 加
  ```ini
  [Service]
  RuntimeMaxSec=12h
  ```

## H. 代码 / 测试 / Git

### H1. `python -m pytest` 报 `No module named pytest`
本项目测试用**标准库 unittest** 写，不装 pytest 也能跑：
```bash
python3 -m unittest discover -s tests -v
```
（PC 上想装：`pip install pytest`）

### H2. `python -m health_monitor ...` 报 `No module named health_monitor`
**必须在 `rpi/` 目录下运行**（那是包根）：
```bash
cd ~/raspberry-health-monitor/rpi
```

### H3. 提交时 `git status` 冒出一堆 `data/`、`*.db`
`.gitignore` 已排除，**别 `git add -A`**；只 add 你改的源码文件。
若已被跟踪：`git rm --cached <文件>` 然后提交。

### H4. 改了文件但另一个同学说"拉下来没这个文件"
**判据**：`git ls-files <路径>` 有没有列出它。
如果工作树里有、`git ls-files` 没有 ⇒ **被 `.gitignore` 忽略了**：
```bash
git check-ignore -v <文件>      # 看是哪条规则忽略的
```
本项目已踩过这个坑（`data/` 没加前导斜杠，把安卓的源码包忽略了），
详见项目 `ERROR.md` 的 E16 与工作区 `memory/29`。

### H5. 提交信息里有双引号导致提交失败
用文件方式提交（PowerShell 会把引号拆坏）：
```bash
git commit -F msg.txt
```
