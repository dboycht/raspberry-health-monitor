## 3. DHT11 数据线被拉死到地：判据与三条排查（**2026-09-25 那一次的排查记录**）

> ℹ️ 结论先行：**这条后来被证明是"接线被动过"造成的临时状态** ——
> 同一晚换回原模块后 DHT11 又能读出真实值，基础版还用同一根线连续采了 111 个样本。
> 所以第 1 节把它标成 ✅（**代码侧没问题**），这里保留的是**排查方法**：
> 下次再遇到"读不到"，按这三条走，能分清"线/模块的问题"还是"树莓派这一侧的问题"。

**判据（可直接复现）**：在 `rpi/` 下跑

```bash
python3 scripts/diag_pin_levels.py --dht
```

读到 **上拉=0、下拉=0**（那次实测三态全是 0/50）就落在这一条：

> 数据线被**拉死到地**：DATA 接到了 GND，或线与 GND 短路。

对照实验（同一时刻量其它脚，排除"是树莓派坏了"）：

| 物理脚 | 上拉时高电平 | 下拉时高电平 | 结论 |
| --- | ---: | ---: | --- |
| **7（GPIO4，DHT11 DATA）** | **0/20** | 0/20 | **被拉死到地** |
| 11（GPIO17，PIR 预留） | 20/20 | 0/20 | 正常（空脚） |
| 13（GPIO27，按键预留） | 20/20 | 0/20 | 正常 |
| 15（GPIO22，LED 预留） | 20/20 | 0/20 | 正常 |

⇒ **只有数据脚那一根是死的**，说明问题在**那根线/那个模块**，不在树莓派。

**按这个顺序查（每步都有判据，别跳步）**

1. **拔掉 DHT11 模块，再量一次 GPIO4**：
   - 变成"上拉=1 / 下拉=0" ⇒ **模块或线的问题**（模块内部对地短路、或线插错列）；
   - 仍然是"上拉=0 / 下拉=0" ⇒ **树莓派这一侧的脚被接通到地**：
     检查杜邦线是否插错排（物理脚 7 的邻居是脚 6 = **GND**，**插错一格就会正好是这个症状**），
     以及面包板是否把 DATA 插进了 GND 那一列（**面包板每列纵向导通**）。
2. **确认模块针脚顺序**：DHT11 三针模块常见丝印 `VCC / DATA / GND`（或 `+ / OUT / -`），
   **反插会把 DATA 直接怼到 GND**；裸四针传感器则要自己接 4.7kΩ~10kΩ 上拉。
3. **万用表蜂鸣档**：模块 GND ↔ 树莓派 GND（应响）、模块 DATA ↔ 物理脚 7（应响）、
   DATA ↔ GND（**不应响**；响就是短路）。

> ⚠️ 与 2026-09-24 那次的区别：那次是"上拉=1、下拉=1"（**拉死到 3.3V**，DATA 接进了电源列），
> 这次是"全 0"（**拉死到地**）。**两种症状原因不同，别照抄上次的结论。**
