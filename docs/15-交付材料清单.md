## 3. 现在能真机演什么（建议的答辩顺序）

1. **环境监护**：`serve --real` → 状态页 `http://<IP>:8080/`（三面板 + 6 张指标卡 + 4 张趋势图）
2. **报警链路**：临时压低室温上限 ⇒ 蜂鸣 + **LED 变黄** + **彩屏/字符屏上字** + 状态页横幅
   ⇒ 点面板或拨"消音" ⇒ **只停响、灯仍亮**（`docs/07` A6 同款判据）
3. **按需测血氧**（T14）：到点叫人（蜂鸣 2 声 + 两块屏提示）→ 短按接受 → 手指放上 → 屏上给结果
   （⚠️ 现场演示时**注意别和"报警文案"抢屏**：提示与报警都优先于信息页）
4. **手机端**：装 `app-debug.apk` → 填地址 → 四张卡真值 / 缺失值显示"请将手指放好" / 长按 1.5 秒求助
   （⚠️ **debug 包名带 `.debug` 后缀**）
5. **云端只读**：把手机切到只有移动数据（不连树莓派所在网）⇒「云端」页仍能看到"上次上报"，
   并**自动提示"数据已超过 10 分钟没更新"**（这正是这一页的价值，也是它的边界）
6. **断网仍能本地报警**：拔网线/关 WiFi ⇒ 本地报警照常（云端那条链路会显示"已知离线"）

## 4. 三个"别踩"的操作要点（都实测踩过）

1. ⚠️ **跑 `hardware_test.py` 前必须先停服务** —— 两者抢同一批 GPIO，
   服务在跑时会报 **`GPIO busy` 假红**（实测 4 项：motion / tft / status_led / sos_button）。
   正确顺序：停服务 → 体检 → 再起服务。干净那次是 **20 PASS / 0 FAIL**。
2. ⚠️ **切屏失败先看有没有"提示"占屏**：`spo2` 叫人提示与报警文案**都优先于**手动页/轮播
   （`/api/v1/health` 的 `outputs` 里会看到 `page=-1`）。别误判成"屏幕坏了"。
3. ⚠️ **安卓构建要 `JAVA_HOME=JDK 21`**：本机默认 `java` 是 25，AGP 会失败（报错只有一行 `25.0.3`）。
   配方见 [`../android/README.md`](../android/README.md)；构建后用 `adb install -r` 装。
