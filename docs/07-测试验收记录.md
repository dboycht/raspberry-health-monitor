## 6.3 · 本轮顺带量清的一个老问题：**停服务后约 60 秒内无法重新绑端口**

老早记的"`stage_run --stop` 偶发端口占用"这次量到了根因，**它不是偶发**：

```
t=  0.0s  TIME_WAIT= 8  can_bind=False      ← 停服务后立刻
...
t= 57.1s  TIME_WAIT= 8  can_bind=False      ← 57 秒后仍然绑不上
（另一次实测：新实例起来后报 `端口 8080 无法绑定`，本探针"等 61 秒"之后才成功）
```

**根因**：本项目的服务器**刻意不让 socket 复用地址**（`allow_reuse_address=False`，
理由是 ERROR.md **E7**：否则 Windows 上第二个实例也能绑上同一端口）
⇒ 只要 8080 上还有 `TIME_WAIT`（服务退出前有过 in-flight 连接，例如面板轮询的 keep-alive），
新的 `bind` 就会被内核拒绝，**实测约 60 秒**（= Linux `TIME_WAIT` 默认时长）。

**影响**：`stage_run --stop` 之后立刻重启、或 `serve` 重启，会看到"端口无法绑定"并退出（`rc=2`）。
**处置**：**2026-10-01 已按用户拍板修掉**（改成"**按平台**"）：`net/web.py` 新增
`allow_reuse_address()` —— **Linux 允许** `SO_REUSEADDR`、**Windows 禁止**。
依据是同一个开关在两平台上是两件事：Windows 上它会让**第二个活着的实例也能绑同一端口**
（E7 的原场景）；Linux 上它**只**放开 `TIME_WAIT`，**不允许**第二个活着的监听者
⇒ 防双开不受影响，却能把 60 秒等待去掉。`probe_port` 与 `make_server` 共用这一个函数（同口径）。

**真机复验（13/13 PASS，`_scratch/board_reuse_and_outputs_accept.py`）**：

| 判据 | 实测 |
| --- | --- |
| 停服务后**立刻**重启 | ✅ 从 kill 到 API 就绪 **1.5 秒**（含进程启动），日志**无**"端口无法绑定" |
| **S10 回归**：第二个实例 | ✅ 仍 `rc=2`、仍打印端口占用文案、**仍然一个器件都没碰**（无 `GPIO busy`/`DeviceInitError`） |
| 第一个实例 | ✅ 毫发无损（`data_age_s=0.0`、无失败、`alarms={}`） |

> ⚠️ Windows 那一侧**没有真机复验**（开发机不跑服务）：`allow_reuse_address()` 在 `os.name == "nt"`
> 时返回 `False`，由单测钉死（含"注入自证"：平台名改三次、取值必须跟着变，防写死成常量）。
