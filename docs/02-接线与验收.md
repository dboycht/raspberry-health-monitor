# 02 · 接线与接线验收（一根一根插，插完必须验）

> **目标**：把所有器件接到树莓派上，并且**在写任何代码之前**先证明"线是对的"。
> **预计 60 分钟**。
> **做完的判据**：本文第 3 节的 `i2cdetect` 能看到 `0x57` 与 `0x27`，
> 且第 6 节的"硬件验收测试单"全绿。

> ⚠️ **别跳步**：接线没验就开服务，会把"线插错"误判成"程序有 bug"，
> 浪费的时间远多于老实验一次。

---

## 1. 引脚总表（先贴一张在工作台上）

**本项目的引脚分配**（BCM 编号与物理脚号都给，插线看物理脚号）：

| 器件 | 信号 | BCM | **物理脚** | 供电 | 备注 |
| --- | --- | --- | --- | --- | --- |
| MAX30102 心率血氧 | SDA / SCL | GPIO2 / GPIO3 | **脚 3 / 脚 5** | 3.3V（脚 1） | I2C 地址 0x57 |
| LCD1602（I2C 转接板） | SDA / SCL | GPIO2 / GPIO3 | **脚 3 / 脚 5** | 5V（脚 2） | 与 MAX30102 **共用总线**，地址 0x27 |
| MCP3002（ADC） | MOSI / MISO / SCLK / CS | GPIO10 / GPIO9 / GPIO11 / GPIO8 | **脚 19 / 21 / 23 / 24** | 3.3V（脚 1） | SPI0.0 |
| TMP36（精密体温） | VOUT | —— | → MCP3002 **CH0** | 3.3V（脚 1） | **不能直接接树莓派**（模拟输出） |
| DHT11 温湿度 | DATA | GPIO4 | **脚 7** | 3.3V（脚 1） | 模块一般自带 10kΩ 上拉 |
| HC-SR501 人体红外 | OUT | GPIO17 | **脚 11** | **5V（脚 2）** | 输出 3.3V，可直连 |
| 求救按键 | 一端 / 另一端 | GPIO27 / GND | **脚 13 / 脚 9** | —— | 驱动默认启用内部上拉 |
| 蜂鸣器（有源） | 正极 / 负极 | GPIO18 / GND | **脚 12 / 脚 14** | —— | **串 220Ω~1kΩ 限流电阻** |
| LED 绿 / 黄 / 红 | 阳极 | GPIO22 / GPIO23 / GPIO24 | **脚 15 / 16 / 18** | —— | 每个 LED **串 220Ω~1kΩ**，负极接 GND |
| HC-SR04 超声波（拓展件，默认关闭） | TRIG / ECHO | GPIO5 / GPIO6 | **脚 29 / 31** | **5V（脚 2）** | ECHO 是 5V，**必须经 TXS0102 或分压** |

GND 可用：脚 6 / 9 / 14 / 20 / 25 / 30 / 34 / 39（**所有器件必须共地**）。

> 完整 40-pin 图与"哪些脚空着"见 [`../hardware/01-引脚分配表.md`](../hardware/01-引脚分配表.md)；
> 逐线接法（含线色建议）见 [`../hardware/02-接线图.md`](../hardware/02-接线图.md)。

## 2. 接线顺序（**一步一步来，每步都验**）

### 第 1 步：只接 I2C 器件（MAX30102 + LCD）

这是最容易出问题的一步，单独做。

```
MAX30102:  VIN→脚1(3.3V)   GND→脚6   SDA→脚3   SCL→脚5   INT→不接
LCD1602转接板: VCC→脚2(5V)  GND→脚6   SDA→脚3   SCL→脚5
```

> ⚠️ **MAX30102 的 VIN**：模块上一般有稳压，接 3.3V 最稳；**只有模块明确标了 5V 兼容才接 5V**
> （有些廉价模块的 I2C 上拉电阻接在 VIN 上，接 5V 会把 SDA/SCL 拉到 5V，**可能损坏树莓派**）。

**验证**（这是判据，不是形式）：

```bash
i2cdetect -y 1
```
预期：表格里出现 **`0x57`**（MAX30102）与 **`0x27`**（LCD；少数模块是 `0x3F`）。

| 现象 | 最可能的原因 |
| --- | --- |
| 一个都没有 | SDA/SCL 接反了、没共地、器件没供电 |
| 只有 0x27，没有 0x57 | MAX30102 供电或焊接问题（先单独只接它试） |
| 出现 `0x27` 但也有乱码地址 | 线太长/接触不良（换短线） |

### 第 2 步：接 SPI 的 ADC（MCP3002）与 TMP36

```
MCP3002: CLK→脚23  D_OUT→脚21  D_IN→脚19  CS→脚24  VDD/VREF→脚1(3.3V)  VSS→脚6
TMP36:   +VS→脚1(3.3V)   GND→脚6   VOUT→MCP3002 的 CH0
```

> ⚠️ **TMP36 绝不能接 5V**：它的输出会超过 ADC 的参考电压（3.3V），读数饱和甚至损伤引脚。
> ⚠️ 裸 TMP36 是 SOT-23 表贴封装，**必须焊在转接板上**。

**验证**：

```bash
ls -l /dev/spidev0.0          # 必须存在
```

### 第 3 步：接 GPIO 类（DHT11 / PIR / 按键 / 蜂鸣器 / LED）

按第 1 节的表插线。要点：

- **蜂鸣器与每个 LED 都要串限流电阻**（220Ω~1kΩ）；LED 长脚（阳极）接 GPIO，短脚接 GND。
- **HC-SR501 的 VCC 必须接 5V**（脚 2），接 3.3V 会工作不稳、探测距离变短。
- **按键不需要外接电阻**（驱动启用内部上拉）；若你的模块自带上拉/输出高电平，
  后面把配置里的 `pull_up` 改成 `false`（见下）。

### 第 4 步（可选）：拓展件 HC-SR04

本项目默认**关闭**该器件（配置里 `"enabled": false`）。要启用：

```
HC-SR04: VCC→脚2(5V)  GND→脚6  TRIG→脚29(GPIO5)
         ECHO→【TXS0102 电平转换 或 1kΩ+2kΩ 分压】→脚31(GPIO6)
```
然后在 `rpi/config/devices.json` 里把 `distance` 的 `enabled` 改成 `true`。

## 3. 接线自检（3 条命令，插完就验）

```bash
# ① I2C 总线上有谁
i2cdetect -y 1
```
预期：**`0x57` 和 `0x27`（或 0x3F）都在**。

```bash
# ② SPI 节点在
ls -l /dev/spidev0.*
```

```bash
# ③ GPIO 没被别的进程占用（重复启动服务会占用；先确认没有残留进程）
pgrep -af health_monitor || echo "没有残留进程（正常）"
```

**肉眼检查（很重要）**：
- [ ] 所有器件的 **GND 都和树莓派共地**（不是只接了一部分）
- [ ] 3.3V 与 5V **没接反**（MAX30102/DHT11/TMP36/MCP3002 走 3.3V；LCD/PIR/HC-SR04 走 5V）
- [ ] 没有裸露的线头互相碰到（尤其 5V 与 GND 之间）
- [ ] 树莓派**关机后再插拔线**（带电插拔容易烧器件）

## 4. 硬件验收测试单（**一步到位**）

项目自带一个逐项验收脚本，它会：检查平台/设备节点/依赖 → 扫 I2C → **逐个器件读数并判断是否物理合理**
→ 交互式确认 LED/LCD/蜂鸣器/音箱/按键。失败时**直接给出排查命令**。

```bash
cd ~/raspberry-health-monitor/rpi
sudo python3 scripts/hardware_test.py
```

输出长这样（示意）：

```
[PASS] 运行平台      机器架构 aarch64，型号 Raspberry Pi 5 Model B
[PASS] I2C 总线 /dev/i2c-1
[PASS] SPI /dev/spidev0.0
[PASS] python 模块 smbus2 / spidev / gpiozero
[PASS] I2C 总线扫描   扫到的地址：0x27, 0x57
[PASS] 打开 vitals（max30102）
[PASS] 心率数值（MAX30102）   读数 68.2 ~ 71.4（中位 69.8）
...
>>> 观察 LED：现在依次点亮 绿 → 黄 → 红（各 1.5 秒）
    三种颜色都亮了吗？[y/N]
```

**分项做法**（只想验某一件）：

```bash
sudo python3 scripts/hardware_test.py --skip-output      # 跳过会发声/闪灯的交互项
sudo python3 scripts/hardware_test.py --json report.json # 导出报告（贴进课程报告很有用）
```

## 5. 逐器件"这样才算对"

| 器件 | 成功判据 | 常见的"看起来对其实不对" |
| --- | --- | --- |
| MAX30102 | 手指盖住窗口 10 秒 → 心率 55~100、血氧 95~100 | 心率恒 `--`：手指没盖严 / 环境强光 / `finger_detected=false` |
| DHT11 | 室温 15~35°C、湿度 30~80% | 读数一直"缓存"：读取间隔 <2 秒（DHT11 硬件限制） |
| TMP36+MCP3002 | 体温 35~38°C；ADC 原始值 200~300 之间 | 恒 0 或 1023 ⇒ **先查 SPI 控制字与 CS**（见 05-排错） |
| HC-SR501 | 走到 3 米内挥手臂 → 状态变 `detected` | 一直 `idle`：热身没到 1 分钟 / VCC 接了 3.3V |
| LCD1602 | 显示 `RPI HEALTH TEST` 两行英文 | 全黑 ⇒ 调背面对比度电位器；花屏 ⇒ 地址或初始化序列 |
| 蜂鸣器 | 响 2 声 | 无声 ⇒ 型号是**无源**（需 PWM）或没串电阻接错极性 |
| LED | 绿/黄/红依次亮 | 只有一种亮 ⇒ 共阳/共阴接法与 `active_low` 不匹配 |
| 按键 | 按下有事件 | 一直触发 ⇒ 模块自带上拉，需把 `pull_up` 设为 `false` |
| 蓝牙音箱 | 播报"设备测试完成" | 没配对；**不影响其它功能**（蜂鸣器+LED 照样报警） |

## 6. 器件"能用"之后：把它们逐个打开

配置默认**只启用核心件**。若你接了拓展件（或想关掉某个没接的件），改
`rpi/config/devices.json`：

```json
"distance": {
  "driver": "hc_sr04",
  "enabled": true,          // ← 从 false 改 true
  "optional": true,
  "read_interval_s": 5.0,
  "params": { "trig_pin": 5, "echo_pin": 6 }
}
```

> 改完跑一次 `python3 scripts/validate.py`（会检查**引脚冲突**）；
> 再跑 `python3 -m health_monitor selfcheck --real` 确认每个器件都能打开。
