## 4. 期间踩的坑（都修了，且都补了防御）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 公钥明明装上，仍 `Permission denied (publickey)` | Windows 下 `.pub` 是 **CRLF**，`\r` 写进 `authorized_keys` 后 sshd 解析失败 | 安装前**规范化**（去 CR/BOM）并**内联公钥**安装，不走管道 |
| 2 | `ssh-copy-id` 报 `WinError 193 不是有效的 Win32 应用程序` | Windows 上命中的是 **Git 自带的 Bash 脚本**，不能直接执行 | 只认 `.exe/.cmd/.bat`，否则退回等效命令 |
| 3 | 树莓派上"文档一致性"检查失败、本地却通过 | 检查器的**注入自测**硬编码 `docs/README.md` 当"真实文件" —— 只在"仓库根 == 项目根"时成立 | 自测**临时造文件**来验证"不误报" |
| 4 | 树莓派上缺 `android/.../data/*.kt`，文档检查报悬空 | 打包时用了 `tar --exclude=data`，GNU tar 的排除模式**无锚定概念**，把任意层级的 `data` 目录都吃掉了（与项目历史上 `.gitignore` 的坑同类） | 改用**白名单暂存目录**打包 |
| 5 | `.gitignore` 里的 `/config/devices.local.json` **没生效** | 加了前导斜杠 → 锚定到仓库根，而文件其实在 `rpi/config/` 下 | 改成不带斜杠的 `devices.local.json`，并用 `git check-ignore` 实测 |
| 6 | 数据点发不出去、`published=0`、毫无提示 | 探针用了**自造的键**（`probe_temp`），不在 `stream_map` 里 → 映射后没有任何字段 → 静默 return | ① 探针改用真实键；② 代码**必须留痕**：累加 `skipped_empty` + 记 warning |
| 7 | 发布成功但**收不到平台回执** | 配置里 `topic_template` **少了 `$sys/` 前缀** → 订阅到错误主题，丢掉了"是否被接收"的唯一硬证据 | 代码**新增校验**：不是以 `$sys/` 开头就直接报错并说明后果 |
| 8 | 同一份测试：开发机绿、树莓派红 | 新测试依赖"这台机器上有没有 `devices.local.json`" | `load_config(..., use_local=False)` 显式隔离环境；测试自己造临时覆盖文件 |

> 这些经验已写入项目 `ERROR.md`（详录）。
