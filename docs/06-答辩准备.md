## 3. 现场演示脚本（10 分钟，照着走）

### 3.0 开场前 5 分钟检查（**别在老师面前才发现**）

- [ ] 树莓派已上电、服务已启动（`serve --real`）
- [ ] HDMI/电脑浏览器已打开 `http://<树莓派IP>:8080/`（状态页）
- [ ] 手机 App 已打开并显示数据（WiFi 已连、地址已配好）
- [ ] 蓝牙音箱已配对（没配好也不影响，提前说明"语音走音箱，没配好时蜂鸣器+LED 照常报警"）
- [ ] OneNET 控制台已登录并停在设备数据流页面（要做上云演示时）
- [ ] 手指擦干净（心电/血氧传感器对皮肤油脂敏感）
- [ ] 关闭树莓派屏幕休眠（否则演示中途黑屏）

### 3.1 第 1 分钟：一句话介绍 + 架构图

> "我们做的是**居家老人健康与安全监护系统**。树莓派 5 作为**边缘节点**，
> 采集心率血氧、体温、环境温湿度与人体活动；**在本地完成判定与声光报警**，
> 断网也能工作；数据同时上报 **OneNET 云平台**并由规则引擎转发回应用，
> 子女可以用手机 App 远程查看。整体是**端 — 边 — 云 — 应用**四层。"

（指着 README 里的架构图讲，30 秒）

### 3.2 第 2~4 分钟：硬件与接线

- 亮出实物，指出：**I2C 总线**（MAX30102 + LCD 共用，靠地址区分）、
  **SPI**（MCP3002）、**单总线**（DHT11）、**GPIO**（PIR/按键/蜂鸣器/LED）。
- 主动讲这个"必被问"的点：
  > "树莓派**没有任何模拟输入引脚**，所以 TMP36 这种模拟输出的传感器**必须经 ADC**（MCP3002）；
  > 而 MAX30102 是 I2C 数字器件，**不能**接 ADC —— 接口类型根本不匹配。"

### 3.3 第 4~6 分钟：正常监护 + 状态页

- 手指贴住 MAX30102，等 10 秒 → 状态页出现心率/血氧
- 指出状态页上的**六张卡 + 设备状态表**：
  > "每一路传感器都有独立的读取周期、失败计数和最后错误。读不到就显示**未知**，不会填 0。"

### 3.4 第 6~8 分钟：触发报警（**这是得分点**）

按顺序演三种（提前把阈值改好，或现场用现成条件）：

1. **心率异常**：把配置里 `hr_max` 临时改到 60 → 报警（黄灯闪 + 蜂鸣 + 语音 + LCD）
2. **久无活动**：把 `no_motion_timeout_s` 改到 30，人走开 30 秒 → **紧急**报警（红灯）
3. **紧急求助**：按实体按键（或手机长按 1.5 秒）→ SOS（蜂鸣 5 声 + LCD `SOS!`）

每触发一次，**同时指一下手机端**："手机上也同步看到了，并且这是紧急等级。"

### 3.5 第 8~9 分钟：上云

- 切到 OneNET 控制台 → 设备 → **数据流**：现场指出 `heart_rate`、`body_temp` 在实时更新
- （若配了规则引擎）切到树莓派日志 → 指出 `[云端推送] #N` 那一行

### 3.6 第 9~10 分钟：难点与边界（主动交代，避免被问倒）

> "三个我们自己认为最有价值的设计：
> ① **'数据缺失'绝不当作'正常'** —— 读不到就报传感器故障，手机上显示未知，绝不填 0；
> ② **报警不刷屏** —— 冷却 + 迟滞，数值在阈值附近抖动不会反复报警；
> ③ **契约式分层** —— 业务层不认识任何具体器件，换传感器不动业务代码，这也是我们 6 个人能并行开发的前提。
>
> 边界要说清：这是**看护提示**工具，**不是医疗设备**；血氧是 PPG 估算、未与医疗器械标定。"

## 4. 问答预演（老师最可能问的 12 个）

| 问题 | 答题要点（背下来） |
| --- | --- |
| 为什么用 OneNET？ | 国产、免费额度够课程用、支持 MQTT 与数据流；我们用它的**规则引擎**做云云对接，形成完整链路 |
| 树莓派没有模拟引脚，怎么接模拟传感器？ | 外挂 **ADC（MCP3002，SPI）**；TMP36 就是走这条路 |
| MAX30102 能不能接 MCP3002？ | **不能**。它是 I2C 数字器件，ADC 只接收模拟电压 |
| 心率读不到为什么显示"未知"不显示 0？ | 0 bpm 物理上不可能，会被规则判成"心率过低"**误报**；这是我们的安全红线 |
| 断网还能报警吗？ | 能。采集、判定、声光全在本地（边缘计算），上云只是增强 |
| 报警会不会很吵/误报多？ | 冷却时间（同报警 300 秒内只提醒一次）+ 迟滞（回落 3 才解除）+ 手指检测 + 数据陈旧保护 |
| 数据存哪？存多久？ | 本地 SQLite（`/api/v1/history` 可查历史曲线），默认保留 30 天 |
| 手机端怎么连？ | 局域网 HTTP 轮询（3~5 秒）；App 只读 + 消音 + 求助三个写操作 |
| 用了哪些总线？ | I2C（MAX30102/LCD）、SPI（MCP3002）、单总线（DHT11）、GPIO（PIR/按键/蜂鸣器/LED） |
| 系统怎么保证"坏了能发现"？ | 每个设备有读取计数/连续失败/最后错误；所有传感器都没数据时会自发故障报警；手机端能看到"数据已过期" |
| 阈值能改吗？ | 能，`config/devices.json` 的 `thresholds`，改完重启；演示时我们就是靠临时调阈值触发的 |
| 最有技术含量的部分？ | ① 契约式 HAL 分层（并行开发）；② 报警规则引擎的状态/通知分离（迟滞+冷却+恢复）；③ 云云对接链路 |

**反问一句**（加分）：
> "老师，我们的云平台链路里，**规则引擎推送的报文格式**官方文档给了结构但还没实测，
> 我们把它设计成'宽容接收'——先记录原始报文再解析。您觉得这种兜底方式合适吗？"
> （这展示了你对**未验证部分**的诚实与工程判断。）
