## 一、名词解释（报告里第一次出现时最好加一句解释）

| 名词 | 一句话解释 | 在本项目里指什么 |
| --- | --- | --- |
| **端 / 边 / 云** | 端=传感器执行器；边=就近计算与决策；云=集中存储与跨地域访问 | 端=MAX30102 等；边=树莓派；云=OneNET |
| **HAL（硬件抽象层）** | 把"器件差异"关在驱动里，上层只面对统一接口 | `rpi/health_monitor/hal/`（`Device` 基类） |
| **驱动 / 契约** | 驱动=怎么跟某个器件说话；契约=所有驱动必须长什么样 | `open/read/close` + 数据模型 |
| **I2C** | 两根线（SDA/SCL）挂多个器件，靠**地址**区分 | MAX30102(0x57)、LCD(0x27) |
| **SPI** | 四根线（MOSI/MISO/CLK/CS），靠**片选**区分，速度快 | MCP3002（ADC） |
| **单总线 / 1-Wire** | 一根数据线 + 严格时序，双向通信 | DHT11 |
| **GPIO** | 通用输入输出引脚，只能表示高/低电平 | 按键、PIR、蜂鸣器、LED |
| **ADC** | 模数转换器：把**连续电压**变成数字 | MCP3002（10 位，2 通道） |
| **PPG** | 光电容积脉搏波：用光看血液体积变化 | MAX30102 测心率/血氧的原理 |
| **SpO₂** | 血氧饱和度（动脉血中携氧血红蛋白占比） | 由红光/红外 AC/DC 比值估算 |
| **PIR** | 被动红外：探测人体发出的红外变化 | HC-SR501 |
| **边缘计算** | 数据在本地就完成判断与动作，不依赖云 | 断网也能报警 |
| **MQTT** | 轻量发布/订阅协议，物联网常用 | 树莓派 → OneNET 用 MQTT |
| **数据流 / 数据点** | OneNET（旧版）的存储模型：一条"流"下挂多个带时间戳的"点" | `heart_rate` 流下的 `{v:72,t:…}` |
| **规则引擎** | 云平台上的"如果…就…"：收到数据后按条件转发/告警 | OneNET 把数据点 HTTP 推送回我们 |
| **云云对接** | 云平台之间/云与应用之间的对接 | OneNET → 我们自己的服务 |
| **token（鉴权）** | 用密钥算出的短期凭证，替代直接传密钥 | OneNET 的 `version&res&et&method&sign` |
| **停滞/陈旧（stale）** | 数据太久没更新，已不代表当前状态 | 超过 `3×读取周期` 就标陈旧 |

## 二、原理速讲（3 句话版本，答辩够用）

### 1. MAX30102 怎么测心率和血氧？
> 它用两种波长的 LED 照皮肤，光电二极管接收反射光。心脏每次搏动时血液体积变化 ⇒
> 接收光强呈周期性起伏（**PPG 波形**）。数波形周期得到心率；
> 用红光与红外光各自的"交流分量/直流分量"之比 R，代入经验式 `SpO₂ = 104 − 17R` 估算血氧。
> **注意**：这是估算，本项目未做医疗器械标定。

### 2. TMP36 为什么要经 ADC？
> TMP36 输出的是**模拟电压**（10 mV/°C，25°C 时 750 mV），而**树莓派没有任何模拟输入引脚**，
> 只能读"高/低"电平。所以要外挂 ADC（MCP3002，SPI 接口）把电压数字化：
> `raw(0~1023) → V = raw/1023×3.3 → T = (V − 0.75)×100 + 25`。
> 分辨率下限 ≈ 3.23 mV ≈ **0.32°C**。

### 3. 报警是怎么判的？（一句话说清"状态/通知分离"）
> 每轮采集后生成一个**快照**，规则引擎逐条判断阈值；命中就登记"正在报警"，
> 但**是否提醒用户**受**冷却时间**控制（同一条报警 300 秒内只响一次）；
> 数值回落到**迟滞带**之外才解除并发 `all_clear`。
> **关键**：数据缺失时**不判定、也不解除**——"不知道"和"正常"必须分开。

### 4. 通信链路
> 树莓派 HTTP 服务（`/api/v1/*`）供局域网 App 轮询；
> 同时用 MQTT 把数据点上报 OneNET；OneNET 规则引擎再把数据 HTTP 推送回我们的
> `/api/v1/cloud/callback`（云云对接）。

## 三、易混淆概念对照（老师最爱在这里设陷阱）

| 容易混 | 区别 | 在本项目的体现 |
| --- | --- | --- |
| 模拟 vs 数字传感器 | 模拟输出**电压**，数字输出**协议数据** | TMP36 模拟（要 ADC）；MAX30102 数字（I2C） |
| 数字传感器 vs ADC | ADC 的输入**必须是电压** | MAX30102 **不能**接 MCP3002 |
| I2C vs SPI | I2C 两线多器件靠地址；SPI 四线靠片选、更快 | LCD+MAX30102 共 I2C 总线；MCP3002 独占 SPI |
| 有源 vs 无源蜂鸣器 | 有源给电平就响；无源要 PWM 驱动 | 本项目按**有源**实现 |
| 共阴 vs 共阳 LED | 共阴=负极接 GND（高电平点亮）；共阳=正极接 3.3V（低电平点亮） | 配置里的 `active_low` 就是为共阳准备的 |
| 冷却 vs 迟滞 | 冷却=**多久内不再提醒**；迟滞=**回落到多少才解除** | `repeat_cooldown_s` / `hysteresis` |
| 缺失 vs 陈旧 | 缺失=这次没读到；陈旧=读到了但太久没更新 | 两者都置 `None`，但原因不同（看 `sensor_errors`） |
| 请求失败 vs 数据过期 | 前者=手机连不上树莓派；后者=连上了但树莓派没数据 | App 上分别提示；服务端给 `data_stale` 字段 |
| PWM vs 电平 | PWM=按占空比调"平均功率"（调光/调速/无源蜂鸣器） | 本项目 LED 只用亮灭，蜂鸣器按有源直驱 |

## 四、老师可能追问的"深水区"

| 追问 | 怎么答（诚实 + 有判据） |
| --- | --- |
| 你的血氧准吗？ | 不准到医疗级。用经验式估算、无标定；我们只把它当"趋势与异常提示"，报告里已声明边界 |
| 心率算法怎么写的？ | 红外采样 → 快/慢两级移动平均相减取交流分量 → 自适应阈值找波峰 → 相邻峰间隔取**中位数**换算 bpm；用合成波形（60 bpm）验证过，实测 60.0 |
| 采样间隔为什么有的 1 秒、有的 3 秒？ | 每个器件有硬件限制：DHT11 必须 ≥2 秒；MAX30102 要连续采样约 5 秒才能出心率。调度器按各设备自己的周期跑 |
| 多个人同时看会不会很卡？ | 数据量小（每设备每秒一条），SQLite 写入 <1ms；HTTP 用线程化服务器，且默认只服务局域网 |
| 系统失效模式有哪些？ | ① 传感器掉线 → `sensor_fault` 报警；② 全都没数据 → 自发故障报警；③ 网络断 → 本地报警照常；④ 服务挂了 → systemd 自动重启（`install-service.sh`） |
| 怎么保证不是"假装在工作"？ | 三层证据：设备读取计数与最后错误（`/api/v1/health`）、数据年龄 `data_age_s`/`data_stale`、平台回执（OneNET `accepted`/`rejected`） |
| 为什么用"未知"而不是 0 或默认值？ | 0 bpm 会被规则判成"心率过低"从而**误报**；默认值会掩盖故障。显示"未知"并同时报"传感器故障"才是诚实的 |
