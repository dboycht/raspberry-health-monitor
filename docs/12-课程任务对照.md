# 12 · 课程规定任务对照（H：温湿度测量 + 动态曲线）

> 老师给出的规定任务原话（**H：温湿度测量**）：
>
> > **核心任务**：使用树莓派 5 和课程中学习过的温湿度传感器（如 DHT11）周期性读取温度和湿度。
> > 程序保存连续采集的数据，并用 **Matplotlib 绘制动态曲线**；每得到一组新数据，
> > 图中的曲线随之刷新。图中应明确标出温度、湿度以及采样顺序或时间，
> > 使读者能够观察环境参数随时间的变化趋势。
> >
> > **示例输出**：运行后出现动态曲线窗口，温度曲线和湿度曲线随着新数据不断向前延伸。
> > 例如最新一次数据为"温度: 25.0 ℃，湿度: 58%"，下一次采样后图中增加一个新的数据点。
>
> 本文件把这条任务**逐条对上本项目的实现**，并说明"我们比要求多了什么"。
> 结论先说：**要求全部满足，且是跑在整个监护系统里的一个组件，而不是孤立的小练习。**

## 1. 逐条对照

| # | 老师的要求 | 本项目的实现 | 对应文件 / 命令 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 树莓派 5 | 全项目以树莓派 5 为目标平台（GPIO 走 `lgpio`，因 Pi 5 上 `RPi.GPIO` 不可用） | `docs/01-上机准备.md` | ✅ |
| 2 | 课程学过的温湿度传感器（如 DHT11） | **DHT11 驱动**（单总线，GPIO4=物理脚 7），并额外支持 TMP36+MCP3002 精密测温 | `rpi/health_monitor/sensors/dht11.py` | ✅ 超出 |
| 3 | **周期性**读取温湿度 | 采集调度器按**每个设备自己的周期**轮询；DHT11 默认 3 秒（硬件要求 ≥2 秒） | `core/collector.py`、`config/devices.json` 的 `read_interval_s` | ✅ 超出（可配） |
| 4 | 程序**保存连续采集的数据** | 每次采集写入 **SQLite**（`rpi/data/history.db`），提供历史查询接口与保留期清理 | `core/store.py`、`GET /api/v1/history` | ✅ 超出（持久化+清理） |
| 5 | **用 Matplotlib 绘制动态曲线** | 新增 `scripts/live_plot.py`：Tkinter+Matplotlib 窗口，`FuncAnimation` 定时刷新 | `rpi/scripts/live_plot.py` | ✅ **本次补上** |
| 6 | 每得到一组新数据，曲线随之刷新 | 每个采样周期读一次传感器并**追加一个点**，两条曲线同步右移（滚动窗口） | 同上（`--interval` 控制周期） | ✅ |
| 7 | 图中明确标出**温度、湿度**以及**采样顺序或时间** | 左轴 `温度 (℃)`（红）+ 右轴 `湿度 (%)`（蓝），图例齐全；横轴可切 **时间(秒)** 或 **采样序号**（`--xaxis`） | 同上 | ✅ |
| 8 | **示例输出**：动态曲线窗口，最新一次"温度: 25.0 ℃，湿度: 58%" | 窗口标题栏实时显示 `最新一次读数　温度: 25.0 ℃　湿度: 58 %`；终端也同步打印每一组 | 同上 | ✅ |
| 9 | 能观察随时间的**变化趋势** | 滚动窗口（默认保留最近 120 点）+ 底部状态行显示窗口内温度/湿度范围与累计样本数 | 同上 | ✅ 超出 |

## 2. 怎么跑（树莓派上）

```bash
cd ~/raspberry-health-monitor/rpi

# ① 装依赖（只需一次）
sudo apt install -y python3-tk python3-matplotlib

# ② 最短路径：直接读 DHT11 画曲线（不依赖服务）
python3 scripts/live_plot.py

# ② 另一种：复用本项目已落库的连续数据（先起服务）
python3 -m health_monitor serve --real &
python3 scripts/live_plot.py --source api --interval 3

# 常用参数
python3 scripts/live_plot.py --xaxis index        # 横轴改成"采样序号"
python3 scripts/live_plot.py --window 60          # 只保留最近 60 个点
python3 scripts/live_plot.py --save curves.png    # 每帧导出图片（报告插图用）
python3 scripts/live_plot.py --mock               # 没有硬件也能看曲线（模拟数据）
```

**无显示器/想自动出一张图**（适合远程调试或塞进报告）：

```bash
python3 scripts/live_plot.py --mock --headless --duration 30 --save curve.png
```

## 3. 窗口上应该看到什么（截图要点）

```
┌──────────────────────────────────────────────────────────────┐
│  最新一次读数　温度: 25.0 ℃　湿度: 58 %        ← 任务书要求的"示例输出" │
│                                                              │
│  ℃                                                 %         │
│  30 ┤ ●─●─●─●─●─●─●─●                 ← 温度（红，左轴）      60  │
│  25 ┤              ●─●─●─●─●                                   │
│  20 ┤                                 ■─■─■─■─■─■  ← 湿度（蓝，右轴）│
│     └────────────────────────────────────────────────         │
│        0    10   20   30   40   50   60   → 时间 (秒)          │
│  数据源：DHT11（GPIO4） 采样间隔 2.5s 累计样本 62 窗口内 62      │
│  温度范围 22.4~27.1 ℃  湿度范围 51~61 %                        │
└──────────────────────────────────────────────────────────────┘
```

**判据**：
- 两条曲线**随新数据向前延伸**（不是静止的静态图）；
- 标题里的数字**每次采样后变化**；
- 红蓝两色与左右轴对应正确（温度看左轴、湿度看右轴）；
- 采样间隔 ≥2 秒（DHT11 硬件限制，脚本会自动抬高）。

## 4. 为什么"接到本项目里"比"单独写 30 行"更好

| 维度 | 单独写个小脚本 | 本项目里的实现 |
| --- | --- | --- |
| 传感器读取 | 自己写时序（Pi 5 上容易失败） | **成熟的 DHT11 驱动**（含缓存策略、量程校验、单测） |
| 数据保存 | 常常只是内存里的 list（关掉就没了） | **SQLite 持久化** + 历史查询接口 + 保留期清理 |
| 异常处理 | 读失败就崩 | 读失败**如实记为 None**（不补 0）、计数并继续画 |
| 复用性 | 只能在树莓派跑 | `--mock` 无硬件也能跑；`--source api` 复用服务数据 |
| 与整机关系 | 孤立练习 | 是监护系统的**可视化组件**（同一套驱动与存储） |
