> 用途：**团队分工**。每人认领一个或几个器件，照这里的清单一格一格做完即可。
> 接口细节见 [`02-接口规格说明书.md`](02-接口规格说明书.md)；
> 怎么写见 [`04-驱动开发规范与贡献指南.md`](04-驱动开发规范与贡献指南.md)。

## 0. 通用验收标准（每个器件都适用）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| 1 | 文件名 / 类名 / `NAME` / `KIND` 与注册表一致 | `python -m pytest tests/hal -q` |
| 2 | mock 模式可用，且**不创建任何真实硬件对象** | 自己的单测里断言 `bus is None` / `_xx is None` |
| 3 | 未 `open()` 就 `read()` 抛 `DeviceNotReady` | 单测 |
| 4 | `close()` 可重复调用且不抛异常 | 单测 |
| 5 | 数据缺失为 `None`（**不是 0**），缓存值有标注 | 单测 + 代码检查 |
| 6 | 失败时 `status()["fault_count"]` 增长、`last_error` 有内容 | 用 `MockBus.fail_next()` 注入失败 |
| 7 | `describe()` 写清**物理脚号** | `python -m health_monitor selfcheck --mock` 能打印出来 |
| 8 | **纯算法拆成可单测的函数/类**（不碰硬件） | 单测里不 new 硬件对象也能测它 |
| 9 | 文件头有：用途 / 接线表 / 设计要点 / 负责人 | 人看一眼 |
| 10 | 全部单测通过 | `python -m pytest tests -q` |

## 1. 传感器组 A：生理与环境

### 1.1 MAX30102 —— 心率血氧传感器（驱动名 `max30102`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/max30102.py` · 类 `Max30102` |
| 接口 | **I2C**，7 位地址 `0x57`，总线 1 |
| 接线 | `VIN`→3.3V（物理脚 1 或 17）· `GND`→GND（脚 6）· `SDA`→GPIO2（脚 3）· `SCL`→GPIO3（脚 5）· `INT` 可不接 |
| 关键寄存器 | `0x09` 模式配置（复位 `0x40`、SpO2 模式 `0x03`）· `0x0A` SpO2 配置 · `0x0C`/`0x0D` LED 电流 · `0x04`/`0x06` FIFO 读写指针 · `0x07` FIFO 数据 · `0x21` PART_ID（应为 `0x15`） |
| 必须实现 | 复位与初始化序列、FIFO 读取（每样本 3 字节 / 18 位）、手指检测、心率与血氧估算 |
| 数据模型 | `VitalSignsSample(heart_rate_bpm, spo2_percent, finger_detected, quality)` |
| 特别要求 | ① **没检测到手指时心率/血氧必须是 `None`**；② 心率算法要拆成**纯函数**，用合成波形（60 bpm 周期）单测，断言结果落在 55~65；③ 采样窗口不足时返回 `ok=False`（不要给错值） |
| 常见坑 | 上电后需等待复位完成；FIFO 溢出要清指针；红光/红外两路都要读；I2C 时钟拉伸可能导致读失败（要重试） |

### 1.2 DHT11 —— 温湿度传感器（驱动名 `dht11`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/dht11.py` · 类 `Dht11` |
| 接口 | **单总线**，数据脚默认 BCM 4（物理脚 7），需 4.7k~10k 上拉（模块通常自带） |
| 接线 | `VCC`→3.3V（脚 1）· `GND`→GND（脚 6）· `DATA`→GPIO4（脚 7） |
| 特别要求 | ① **两次读取间隔必须 ≥2 秒**（硬件限制）；不足时返回上次值并标 `is_cached=True`；② 量程校验（0~50°C、20~90%RH），超范围判坏点 |
| 数据模型 | `AmbientSample(temperature_c, humidity_percent, is_cached)` |
| 常见坑 | 树莓派 5 上 `RPi.GPIO` **不可用**（GPIO 架构变了），要用 `gpiozero` + `lgpio`；手工 bit-bang 时序在 Pi 5 上不稳定，**优先用 gpiozero 的 `DHTSensor`/`DHT11`** |

### 1.3 组长验收问题（答辩预演）

1. 为什么心率读不到时不能填 0？（答：会被判成"心率过低"误报，且历史曲线会出现假跌落）
2. DHT11 为什么要等 2 秒？（答：器件内部采样周期限制，读太快拿到旧值甚至通信失败）

## 2. 温控组 B：模拟量与 ADC

### 2.1 MCP3002 —— 10 位 ADC（驱动名 `mcp3002`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/mcp3002.py` · 类 `Mcp3002` |
| 接口 | **SPI0**：CLK=脚 23 · D_OUT(MISO)=脚 21 · D_IN(MOSI)=脚 19 · CS=脚 24（也可软件片选） · VDD/VREF=脚 1（3.3V） · VSS=脚 6 |
| 必须实现 | `read_raw(channel) -> int(0..1023)`、纯函数 `raw_to_voltage(raw, vref=3.3)` |
| SPI 时序 | 发 **3 字节** `[cmd, 0x00, 0x00]`，回读 3 字节，10 位结果 = `((r[0] & 0x03) << 8) \| r[1]`；控制字节位序：`bit7=0` 前置、**`bit6=START=1`、`bit5=SGL/DIFF=1`（单端）、`bit4=通道号`、`bit3=MSBF=1`** ⇒ 通道 0 = `0x68`，通道 1 = `0x78` |
| 科目考点 | 为什么树莓派需要 ADC？（**树莓派没有模拟输入引脚**，模拟器件必须经 ADC） |
| 常见坑 | 控制字位序写反（表现为读数恒为 0 或 1023）；CS 未拉低/未拉高；SPI 未在 `raspi-config` 里开启 |

### 2.2 TMP36GT9Z —— 精密温度（驱动名 `tmp36`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/tmp36.py` · 类 `Tmp36`（**内部组合一个 `Mcp3002`**，不要复制 SPI 代码） |
| 接口 | **模拟输出**，必须经 MCP3002 读取 |
| 接线 | `+VS`→**3.3V**（脚 1，⚠️ 绝不能接 5V）· `GND`→GND（脚 6）· `VOUT`→MCP3002 CH0 |
| 换算 | `V = raw / 1023 × vref`；`T(°C) = (V − 0.75) × 100 + 25`（10 mV/°C，25°C → 750 mV） |
| 数据模型 | `PrecisionTempSample(temperature_c, raw_adc, voltage_v)` —— **三个都要填**（报告要写换算推导） |
| 必须实现 | 纯函数 `voltage_to_celsius(v, v25=0.75, mv_per_c=10.0)`、量程校验（-40~125°C）、`calibration_offset_c` 标定偏移 |
| 标定方法 | 冰水 0°C / 室温 / 沸水 ~100°C 各测一次，`Δ = 参考值 − 读数`，取平均写入 `calibration_offset_c` |
| 常见坑 | 封装是 **SOT-23 表贴**，裸芯片必须焊在转接板上；供电接 5V 会导致输出超过 ADC 量程 |

### 2.3 组长验收问题

1. 为什么 TMP36 不能直接接树莓派？（答：模拟输出，树莓派无模拟引脚）
2. 1 LSB 对应多少度？（答：`3.3/1023/0.01 ≈ 0.32°C`，这就是本项目精密测温的分辨率下限）
3. 用 MCP3002 读 MAX30102 行不行？（答：**不行**——MAX30102 是 I2C 数字器件，ADC 只接收模拟电压）

## 3. 活动组 C：人体感知

### 3.1 HC-SR501 —— 人体红外（驱动名 `hc_sr501`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/hc_sr501.py` · 类 `HcSr501` |
| 接口 | GPIO 数字输入（有人=高电平） |
| 接线 | `VCC`→**5V**（脚 2）· `GND`→GND（脚 6）· `OUT`→GPIO17（脚 11）· 输出 3.3V 可直连，无需电平转换 |
| 必须实现 | 软件去抖（默认 0.2s）、`seconds_since_motion() -> float`、上电稳定期 `settle_s` 内忽略误触发 |
| 数据模型 | `MotionSample(state, active_for_s)` |
| 特别要求 | 读失败必须报 `MotionState.UNKNOWN`，**不许假装 IDLE**（会把"设备坏了"误判成"老人久未活动"） |
| 操作要点 | 模块上两个电位器：延时（人走后 OUT 保持多久）、灵敏度；**单次触发 vs 可重复触发**要用跳线选可重复 |

### 3.2 HC-SR04 —— 超声波测距（**拓展件，默认关闭**，驱动名 `hc_sr04`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/hc_sr04.py` · 类 `HcSr04` |
| 接口 | `TRIG` 输入（发 10µs 高电平）、`ECHO` 输出（回波高电平宽度） |
| 接线 | `VCC`→**5V**（脚 2）· `GND`→脚 6 · `TRIG`→GPIO17（脚 11） · `ECHO`→**经 TXS0102 电平转换**后接 GPIO27（脚 13） |
| ⚠️ 安全 | **ECHO 输出 5V，树莓派 GPIO 只有 3.3V 容忍**——必须经 TXS0102 或电阻分压，否则可能损坏 GPIO |
| 换算 | 声速 `v = 331.3 + 0.606 × T` m/s；距离 `d = v × t / 2`。20°C、5800µs ≈ 100cm |
| 超时策略 | 回波超时返回 `RangeSample(ok=False, error=...)`，**不抛异常**（测距是高频易失败量）；默认重试 3 次取中位数 |
| 常见坑 | 树莓派 5 上纯 Python 测脉宽有 ±20~50µs 抖动（≈±0.3~0.9cm）；2cm 内与 400cm 外无效 |

## 4. 交互输出组 D：显示与声音

### 4.1 LCD1602 —— 液晶显示（驱动名 `lcd1602`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/outputs/lcd1602.py` · 类 `Lcd1602`（继承 `OutputDevice`） |
| 接口 | **I2C**（PCF8574 转接板），常见地址 `0x27` / `0x3F`（驱动要自动探测） |
| 接线 | `VCC`→5V 或 3.3V（脚 2/1）· `GND`→脚 6 · `SDA`→脚 3 · `SCL`→脚 5 |
| 必须实现 | 4 位 HD44780 初始化序列、`send(DisplayCommand)`、`clear()`、背光控制、`read()` 返回当前两行 |
| ⚠️ 限制 | **只能显示 ASCII，中文会花屏**——驱动必须把非 ASCII 安全降级；界面文案用英文（`HR 72 bpm` / `ALARM: HR HIGH`） |
| 常见坑 | 与 MAX30102 共用 I2C 总线（地址不同，互不影响）；初始化必须是 `0x33 → 0x32 → 0x28 → 0x08 → 0x01 → 0x06 → 0x0C` 顺序；写太快需要延时 |

### 4.2 蓝牙音箱 —— 语音播报（驱动名 `bt_speaker`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/outputs/bt_speaker.py` · 类 `BtSpeaker` |
| 方案 | 本地 TTS：`espeak-ng -v zh -s 150 -w out.wav "文本"` → `aplay out.wav` |
| 必须实现 | `send(SpeakCommand)`、**可注入的执行器**（`runner` 参数，单测注入假执行器，绝不真的出声）、文本去重窗口（10 秒内同句不重复）、`self_check()` 检查 `espeak-ng`/`aplay` 是否存在 |
| 系统配置 | `sudo apt install -y espeak-ng alsa-utils`；蓝牙配对：`bluetoothctl` → `pair` → `trust` → `connect`；音频路由选 `bluealsa` 或 `pulseaudio` |
| 常见坑 | 树莓派音频默认走 HDMI，要选到蓝牙 sink；TTS 与播放要串行，否则两句话叠在一起 |

### 4.3 蜂鸣器（驱动名 `buzzer`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/outputs/buzzer.py` · 类 `Buzzer` |
| 接线 | 有源蜂鸣器：`+`→GPIO18（脚 12，串 220Ω~1kΩ 限流电阻）· `−`→GND（脚 14） |
| 必须实现 | `send(BeepCommand(times, on_ms, off_ms))`、`beep_on()/beep_off()/silence()`、**单次总时长上限 10 秒**（防代码 bug 导致长鸣不止） |
| 常见坑 | 无源蜂鸣器需要 PWM 才能响（要区分有源/无源）；直接接 GPIO 电流过大会损伤引脚 |

### 4.4 LED 状态指示（驱动名 `led`）

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/outputs/led.py` · 类 `Led` |
| 接线 | 绿→GPIO22（脚 15）· 黄→GPIO23（脚 16）· 红→GPIO24（脚 18）；每路串 220Ω~1kΩ 限流电阻，负极→GND |
| 必须实现 | `send(LightCommand(color, blink))`、**先熄灭其它颜色再点亮目标色**、闪烁定时自动停止、`all_off()` |
| 常见坑 | 忘记限流电阻会烧 LED 或拉低 GPIO 电平；红绿同亮看起来像"黄色故障" |

### 4.5 按键（驱动名 `button`）—— **已完成，作为参考实现**

| 项 | 内容 |
| --- | --- |
| 文件 | `rpi/health_monitor/sensors/button.py` · 类 `Button`（**范本，其他人照抄**） |
| 接线 | 一端 GPIO27（脚 13）· 另一端 GND（脚 9）；启用内部上拉，无需外接电阻 |
| 已实现 | 去抖（可注入时钟，单测不 sleep）、短按/长按判定、`inject()`（仅 mock） |
