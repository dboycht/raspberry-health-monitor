# 安卓端开发指南

> 面向负责手机 App 的同学。**接口的唯一依据是** [`05-安卓通信协议.md`](05-安卓通信协议.md)；
> 本文件讲"怎么把工程跑起来、怎么连树莓派、踩过的环境坑"。

## 1. 工程位置与技术栈

```
android/
├── settings.gradle.kts / build.gradle.kts / gradle.properties
├── gradle/libs.versions.toml        依赖版本集中管理（version catalog）
├── app/
│   ├── build.gradle.kts
│   ├── src/main/AndroidManifest.xml  INTERNET 权限 + 明文 HTTP 配置
│   ├── src/main/res/xml/network_security_config.xml
│   ├── src/main/java/com/dboycht/healthmonitor/
│   │   ├── MainActivity.kt          导航宿主
│   │   ├── data/                    Retrofit 接口、DTO、Repository、地址归一化
│   │   ├── domain/                  报警码→中文、null 安全格式化、严重度映射
│   │   ├── settings/                树莓派地址与 token 持久化
│   │   └── ui/                      dashboard / alarms / settings / about + 组件
│   └── src/test/java/...            JVM 单测（不依赖网络与真机）
└── README.md                        构建与连接说明
```

- 语言/UI：**Kotlin + Jetpack Compose**
- 网络：**Retrofit + kotlinx.serialization**（不用 Gson：字段缺失必须映射成 `null`，
  而 Gson 对 `Int` 字段的缺失会静默给 0 —— 那会直接违反协议 §4.1 的渲染硬要求）
- 轮询：`/api/v1/current` 3~5 秒一次，**在 `onStop()` 停止轮询**（省电，也避免后台被杀）

| 项 | 值 |
| --- | --- |

| JDK | `C:\Program Files\Microsoft\jdk-21.0.8.9-hotspot` → 构建前设 `JAVA_HOME` |
| Gradle | **不要用 `gradlew`**：wrapper 会联网下载发行包，而本机 TLS 被加速器解密阻断（`PKIX path building failed`）。用已解包的 Gradle：`%USERPROFILE%\.gradle\wrapper\dists\gradle-8.13-bin\5xuhj0ry160q40clulazy9h7d\gradle-8.13\bin\gradle.bat` |

## 3. 连树莓派

1. 树莓派上启动服务：
   ```bash
   cd ~/raspberry-health-monitor/rpi
   python3 -m health_monitor serve --real --host 0.0.0.0 --port 8080
   ```
2. 查树莓派局域网 IP：`hostname -I`（通常是 `192.168.x.x`）。
3. 手机与树莓派**连同一个 WiFi**，在 App 设置页填：`http://192.168.x.x:8080`
   （App 会自动补 `http://` 与默认端口 `8080`；填错会即时提示）。
4. 若树莓派启动时带了 `--token`，在设置页填同样的 token。

**排查连通性的三个层次**（从下往上）：

| 层次 | 命令/动作 | 期望 |
| --- | --- | --- |
| 网络可达 | 手机浏览器打开 `http://<IP>:8080/api/v1/health` | 返回 JSON |
| 服务在跑 | 树莓派上 `curl http://127.0.0.1:8080/api/v1/health` | 返回 JSON |
| 采集正常 | 返回里的 `devices.*.stale` 与 `failures` | `stale=false`、`failures=0` |

## 4. 两个必须做对的 Android 细节

### 4.1 明文 HTTP 白名单（否则请求被系统直接掐掉）

Android 9+ 默认禁止明文 HTTP。局域网是 `http://`，必须在
`AndroidManifest.xml` 的 `<application>` 上加 `android:networkSecurityConfig`，
并在 `res/xml/network_security_config.xml` 里允许明文（或按网段加白名单）：

```xml
<network-security-config>
    <base-config cleartextTrafficPermitted="true">
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </base-config>
</network-security-config>
```

症状指纹：请求抛 `CLEARTEXT communication to 192.168.x.x not permitted by network security policy`。

### 4.2 `null` 必须渲染成"未知"，绝不能渲染成 0

协议 §4.1 的硬要求。树莓派端刻意把"没测到"表示成 `null`（而不是 0），
因为**0 bpm 会被判成"心率过低"**，显示在手机上是吓人的假数据。

建议在 `domain/Formatters.kt` 里收口成一个函数：

```kotlin
fun formatMetric(value: Double?, unit: String, digits: Int = 0): String =
    if (value == null) "--" else "%.${digits}f%s".format(value, unit)
```

配套单测必须断言 `formatMetric(null, "bpm") == "--"`（而不是 `"0bpm"`）。

另外：`finger_detected == false` 时心率区显示"请将手指放好"；
`sensor_failures` 非空时在界面上给**警告色**提示"X 传感器异常"。

## 5. 单测覆盖要求（JVM 单测，不需要真机）

| 用例 | 断言要点 |
| --- | --- |
| 报警码 → 中文 | 照协议 §4.4 的表逐条比对；未知码要有兜底文案 |
| `null` 安全格式化 | `null → "--"`，且**不含 "0"**；0 与 null 是两种显示 |
| 严重度映射 | `0/1/2/3 → 正常/提示/警告/紧急`，颜色与排序 |
| JSON 解析 | 用**真实响应样本字符串**（含 `null` 字段与空 `{}`）断言解析成 Kotlin 的 `null` |
| 地址归一化 | `192.168.1.20` → `http://192.168.1.20:8080`；已带 scheme/端口则不改；`http://x:9999` 保留 9999 |

> 判据：`testDebugUnitTest` 全绿，且上述五类用例**每类至少一条**。
> 网络层用假 Repository/假 HTTP 客户端，**不要在单测里发真实请求**。

## 6. 已知环境坑

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `Could not resolve ...` / `PKIX path building failed` | 本机加速器做 TLS 解密，JDK 不认自签根证书 | 用已解包的 Gradle（见 §2）；不要反复重试 wrapper |
| `SDK location not found` | `local.properties` 缺失 | 按 §2 写入 `sdk.dir` |
| `CLEARTEXT communication not permitted` | 未配置明文白名单 | 见 §4.1 |
| 模拟器连不上树莓派 | 模拟器的 `10.0.2.2` 是宿主机，不是局域网 | 用真机，或让模拟器走宿主机网络并访问宿主机 IP |
| 手机能打开 `health` 但数据全是 `--` | 树莓派端传感器没采到（`devices.*.stale=true`） | 到树莓派上跑 `selfcheck --real` 查接线 |
