## 1. 分层与依赖方向

```
hal/     契约层 ── 谁都依赖它，它不依赖任何人
  ↑
sensors/ outputs/   驱动层 ── 只允许 import hal/，**不许互相 import**
  ↑
core/    业务层 ── 只依赖 hal/ 的数据模型与"驱动名"；**禁止出现具体驱动类名**
  ↑
net/     接口层 ── 只依赖 core/ 暴露的运行时对象
  ↑
service.py / main.py   装配层 ── 唯一知道"所有零件"的地方
```

**一句话判据**：
> 在 `core/`、`net/` 里 `grep` 一下具体驱动类名（如 `Max30102`、`Lcd1602`），
> **一个都不应该出现**。出现了就是分层被破坏。

## 2. Device 基类契约

位置：`rpi/health_monitor/hal/device.py`

```python
class Device(ABC):
    KIND: DeviceKind = DeviceKind.VITAL   # 子类必须覆盖（器件大类）
    NAME: str = "device"                  # 子类必须覆盖（= 注册表里的驱动名）

    def __init__(self, bus=None, mock: bool = False, name: str = "") -> None:
        ...
```

### 2.1 必须实现

| 方法 | 签名 | 要求 |
| --- | --- | --- |
| `open` | `() -> None` | 初始化设备。**mock 模式下只置 `self._opened = True` 后立即返回**，绝不碰硬件。真实模式失败必须抛 `DeviceInitError`，消息里写清排查线索 |
| `read` | `() -> Sample` | 读一次数据，返回对应 `Sample` 子类。开头必须 `self._require_open()`；成功路径调用 `self._note_ok()` |
| `close` | `() -> None` | 释放资源。**幂等**（可重复调用）、**不抛异常**、把 `self._opened = False` |

### 2.2 建议覆盖

| 方法 | 用途 |
| --- | --- |
| `describe() -> dict` | 接线说明。至少含 `name`/`kind`/`mock`/`bus`/`pins`/`notes`；`pins` 用中文写清**物理脚号**。会被 `selfcheck`、`/api/v1/devices`、硬件文档生成脚本读取 |
| `self_check() -> dict` | 轻量自检，返回 `{"ok": bool, "detail": str}`。默认实现 = "能不能读一次"；有更轻手段的（读 WHO_AM_I 寄存器）应覆盖 |
| `status() -> dict` | 运行状态。基类已实现（打开状态、读次数、故障次数、最后错误），一般不用覆盖 |

### 2.3 基类提供的小工具（子类用）

| 方法 | 作用 |
| --- | --- |
| `self._require_open()` | 未 `open()` 就读取时抛 `DeviceNotReady`（防编程错误） |
| `self._note_ok()` | 成功读到数据的记账（读计数 +1） |
| `self._note_fault(exc)` | 异常留痕（故障计数 +1、记录 `last_error`）。**调用后必须把异常继续抛出** |
| `with driver as d:` | 上下文管理器：进入时 `open()`，退出时 `close()` |

### 2.4 mock 模式的硬性要求

> **`mock=True` 时绝不允许**：打开 `/dev/i2c-*`、`/dev/spidev*`、创建 gpiozero/`lgpio` 对象、
> 执行外部命令（如 `aplay`/`espeak-ng`）。

判据（单测里必须断言）：
```python
d = SomeDriver(mock=True)
d.open()
self.assertIsNone(getattr(d, "_btn", None))   # 没有创建真实 GPIO 对象
self.assertIsNone(d.bus)                      # 没有自建真实总线
```

## 3. OutputDevice 基类契约

位置同上。输出类驱动（LCD / 音箱 / 蜂鸣器 / LED）继承 `OutputDevice`：

| 方法 | 要求 |
| --- | --- |
| `open()` / `close()` | 同 `Device` |
| `send(command)` | 执行一条指令（`DisplayCommand` / `SpeakCommand` / `BeepCommand` / `LightCommand`）。**不认识的指令类型必须抛 `UnsupportedError`，不许静默忽略**；执行失败抛 `AlarmDispatchError` |
| `read()` | **建议覆盖**：回读自身状态（LCD 返回 `DisplayStatus`）。返回值必须诚实——**不知道就返回空，不许编造** |

**输出器件的公共纪律**

1. **防吵人**：蜂鸣器单次 `send` 总时长上限 10 秒；音箱同一句话 10 秒内不重复播报（去重窗口可配）。
2. **LED 先熄其它色**：保证任何时刻只有一种状态灯亮（红绿同亮会被看成"黄色故障"）。
3. **LCD 只能显示 ASCII**：中文会花屏；驱动必须把非 ASCII 安全降级（如替换为 `?`），
   界面文案用英文短句（`HR 72 bpm` / `ALARM: HR HIGH`），中文留给手机端与语音播报。
4. **外部命令要可替换**：音箱驱动调 `espeak-ng`/`aplay` 必须通过**可注入的执行器**
   （`runner` 参数），否则单测会真的发出声音。

## 4. 数据模型（采样值）

位置：`rpi/health_monitor/hal/models.py`。所有时间戳都是 **Unix 秒（float，UTC）**，用 `now_ts()` 取。

| 类型 | 关键字段 | 用于 |
| --- | --- | --- |
| `Sample` | `ts, device, ok, error` | 基类；`ok=False` 时 `error` 必填 |
| `VitalSignsSample` | `heart_rate_bpm, spo2_percent, finger_detected, quality` | MAX30102 |
| `AmbientSample` | `temperature_c, humidity_percent, is_cached` | DHT11 |
| `PrecisionTempSample` | `temperature_c, raw_adc, voltage_v` | TMP36 + MCP3002 |
| `MotionSample` | `state, active_for_s`（属性 `.detected`） | HC-SR501 |
| `RangeSample` | `distance_cm, echo_us` | HC-SR04 |
| `ButtonEvent` | `button, action, pressed_for_s` | 按键 |
| `DisplayStatus` | `lines, page` | LCD 回读 |

### 4.1 三条硬性数据纪律

1. **未测出 → `None`，绝不是 0**：`heart_rate_bpm = 0` 是物理上不可能的，
   报警引擎会把它判成"心率过低"从而误报。没贴手指、算法没收敛都填 `None`。
2. **能保留原始量就保留**：MCP3002/TMP36 必须同时给出 `raw_adc` 与 `voltage_v`——
   报告里要写"电压 → 温度"的换算推导，答辩也靠它。
3. **缓存值要标注**：DHT11 因硬件限制（两次读取间隔必须 ≥2 秒）返回上次值时，
   必须把 `is_cached=True`，**不允许把旧值当新数据上报**。

### 4.2 枚举

| 枚举 | 取值 |
| --- | --- |
| `DeviceKind` | `vital` / `ambient` / `precision` / `motion` / `range` / `display` / `audio` / `light` / `button` |
| `MotionState` | `idle` / `detected` / `unknown`（**读失败必须用 unknown，不要假装 idle**） |
| `ButtonAction` | `none` / `press` / `release` / `long_press` / `click`（无事件用 `none`，**不要用 `release` 冒充**） |
| `Severity` | `NORMAL=0` / `NOTICE=1` / `WARNING=2` / `CRITICAL=3`（可直接比较大小） |
| `AlarmCode` | 见 [`08-报警规则表.md`](08-报警规则表.md)（**字符串值改动是破坏性变更**） |

## 5. 报警事件与严重度

```python
@dataclass(frozen=True)
class AlarmEvent:
    ts: float
    code: AlarmCode
    severity: Severity
    message: str        # 面向用户的中文短句，**禁止 markdown 标记**
    value: float | None
    unit: str
    source: str
    detail: dict
```

- `to_dict()` 可直接 JSON 序列化（HTTP / SQLite / MQTT 都用它）。
- **文案不许含 markdown 标记**（`*`、`` ` ``、`#` 等会原样显示给用户，见项目排坑记录 memory/16）。

## 7. 异常体系与错误处理纪律

```
HealthMonitorError
├── ConfigError                 配置错误（启动期就该炸，不要重试）
├── DeviceError
│   ├── DeviceNotFoundError     驱动名/类不存在（装配期错误）
│   ├── DeviceInitError         初始化失败（接线/地址/权限）→ 消息必须含排查线索
│   ├── DeviceIOError           读写失败（**可重试**）
│   │   └── DeviceTimeout       超时（继承 IOError 是刻意的：上层可只抓 IOError）
│   ├── DeviceNotReady          没 open 就用（编程错误）
│   ├── DataInvalidError        数据超量程/不可信
│   └── UnsupportedError        本平台/型号不支持
└── AlarmDispatchError          报警下发失败（蜂鸣器/音箱/网络）
```

**错误处理纪律**（每一条都来自实际踩坑）：

1. **不许吞异常**：`except` 之后必须 `self._note_fault(exc)` 留痕，并把异常继续抛出。
   "静默失败"是本项目一级缺陷——表现为"功能像没实现"，可能整版没人发现。
2. **瞬时错误 vs 数据错误要分开**：总线抖动 → 抛 `DeviceIOError`（上层可重试）；
   读数超量程 → 返回 `ok=False` 的样本或抛 `DataInvalidError`（重试也没用）。
3. **失败也要返回同类型样本**：`read()` 失败时上层不该拿到"未知类型"；
   采集器会按你上次返回的类型造一个 `ok=False` 的样本（驱动无需操心，但要知道这个契约）。
4. **"拒绝启动/拒绝执行"必须能被调用方看到**：错误只写日志不抛异常 = 调用方无从得知。

## 8. MockBus 模拟总线

位置：`rpi/health_monitor/hal/mock_bus.py`。**让没有树莓派的人也能开发和测试。**

```python
bus = MockBus()
# I2C：让 0x57 恒定返回 6 字节
bus.set_i2c_reply(0x57, b"\x01\x02\x03\x04\x05\x06")
# I2C：按请求内容动态应答
bus.hook_i2c(0x27, lambda bus, data: b"\xab")
# I2C 写钩子（记录驱动写了什么寄存器）
bus.hook_i2c_write(0x57, lambda bus, data: None)
# SPI：**必须返回与输入等长**的字节（全双工）
bus.hook_spi(0, lambda bus, data: bytes([data[0] | 0x80, data[1], data[2]]))
# 故障注入
bus.fail_next()                 # 下一个操作抛 DeviceIOError
bus.fail_times(3)               # 连续 3 次失败
# 断言
bus.operations("i2c_write")     # 操作流水
bus.op_count("spi_xfer")        # 次数
```

**纪律**：
- 钩子返回的字节数**必须**等于驱动请求的字节数，否则 `MockBus` 报错
  （钩子与驱动对不上时应当立刻暴露，而不是静默截断）；
- 驱动应当在 `open()` 里 `if self.mock: self.bus = MockBus(); <注册钩子>`，
  **不要**把钩子写在测试里才生效的私有路径上——否则 `serve --mock` 拿不到可用数据。

## 9. 驱动注册表与命名规范

位置：`rpi/health_monitor/hal/registry.py`

```python
MANIFEST = {
    "max30102": DriverSpec("max30102", "health_monitor.sensors.max30102:Max30102",
                           DeviceKind.VITAL, "心率血氧传感器 MAX30102",
                           ("bus", "address", "led_current"), "核心"),
    ...
}
```

**命名规范（必须严格一致，否则契约测试会红）**

| 项 | 规则 | 例 |
| --- | --- | --- |
| 驱动名（注册表键） | 小写、单词间下划线 | `max30102`、`hc_sr501`、`bt_speaker` |
| 文件名 | 与驱动名完全相同 | `sensors/hc_sr501.py` |
| 类名 | 大驼峰 | `HcSr501` |
| 类的 `NAME` 属性 | **必须等于驱动名** | `NAME = "hc_sr501"` |
| `KIND` | 取自 `DeviceKind` | `KIND = DeviceKind.MOTION` |

**`DriverSpec` 字段**

| 字段 | 含义 |
| --- | --- |
| `target` | `"模块路径:类名"` |
| `label` | 中文名（进文档与界面） |
| `params` | 该驱动关心的参数名（文档提示用） |
| `option` | 题包：`核心` / `温控` / `活动` / `拓展` |
| `owner` | 负责人（**团队分工时填这里**，`python -m health_monitor drivers` 会列出） |
| `notes` | 一句话说明（进任务书） |

**配置里的设备名与之无关**：`config/devices.json` 的键（如 `vitals`、`ambient`）是"实例名"，
一个驱动可以被装配成多个实例（例如两个 DHT11 分别测室内外）。

## 10. 编写新驱动的检查清单

复制这张表，逐项打勾后再提交：

- [ ] 文件名 = 驱动名，类名 = 大驼峰，`NAME` = 驱动名，`KIND` 正确
- [ ] 继承 `Device`（输出类继承 `OutputDevice`）
- [ ] `__init__` 第一行 `super().__init__(bus=bus, mock=mock, name=name)`，参数全部有关键字默认值
- [ ] `open()`：mock 立即返回；真实失败抛 `DeviceInitError` 且**消息含排查线索**（提 `i2cdetect` / `raspi-config` / 接线）
- [ ] `read()`：`_require_open()` → 正常路径 `_note_ok()` → 失败 `_note_fault(exc)` 后抛出
- [ ] `close()`：幂等、不抛异常
- [ ] `describe()`：写清**物理脚号**、总线、地址、备注（会被文档与 App 读取）
- [ ] **纯算法从硬件访问里拆出来**（如去抖、单位换算、心率估算），可以脱离硬件单测
- [ ] 数据缺失一律 `None`，绝不填 0；缓存值标 `is_cached`
- [ ] 文件头写了：模块用途 / 接线表（器件引脚 ↔ 树莓派 40-pin 物理脚号）/ 设计要点 / 负责人
- [ ] 单测覆盖：未 open 就 read 抛 `DeviceNotReady`、mock 不碰硬件、正常范围、超量程/坏数据、
      `close()` 幂等、`status()` 计数、故障注入（`MockBus.fail_next`）
- [ ] 断言是**可执行的判据**（如 `assertLess(abs(hr - 60), 6)`），没有恒真断言
- [ ] `python -m pytest tests -q` 全绿
- [ ] 在 `registry.py` 的 `DRIVER_DOCS` 里填了负责人
- [ ] 抄了第三方实现的话，注明**来源 URL + 许可**
