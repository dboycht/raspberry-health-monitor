# 拓展方向（按"投入产出比"排序）

> 本文件给**想继续加分**的同学。当前系统已经完整（"端-边-云"三层、I2C/SPI/单总线/GPIO 全覆盖），
> 下面每条都标注了**改动范围**，方便评估工作量。

## 1. 上云：MQTT 上报（**已实现，默认关闭**）

**现状**：`rpi/health_monitor/net/mqtt.py` 已写好并接入运行时，**不需要改任何现有代码**，
只要在 `config/devices.json` 里填 broker 信息并把 `enabled` 改成 `true`：

```json
"mqtt": {
  "enabled": true,
  "host": "bemfa.com",
  "port": 9501,
  "topic_prefix": "health/room1",
  "client_id": "raspi-health-monitor",
  "username": "",
  "password": "",
  "interval_s": 30
}
```

- 发布主题：`health/<前缀>/reading`（周期读数摘要）、`health/<前缀>/alarm`（报警事件）、
  `health/<前缀>/status`（启动时一次：版本 / 设备数 / 故障设备）；
- 依赖 `paho-mqtt` 是**可选依赖**：没装时只记一条日志并降级为"不发布"，
  采集与本地报警**完全不受影响**；断网或 broker 挂掉也一样（发布失败只计数不抛异常）；
- 发布线程独立 + 有界队列（默认 200）：队列满时**丢最旧的**并计数——
  宁可丢云端数据，也不能让本地报警卡住；
- **隐私最小化**：只发数值、时间戳与报警码；报警的 `detail` 只保留 `recovered_code` 这类安全字段
  （不发本机路径与异常栈）；`sensor_failures` 只发**数量**不发设备名；
- 密码建议用环境变量 `HEALTH_MQTT_PASSWORD`（配置文件留空），或写在自己的 `devices.json` 里
  （该文件已被 `.gitignore` 排除，不会进仓库）；
- 上云状态可在 `GET /api/v1/health` 的 `mqtt` 字段看到
  （`enabled` / `connected` / `published` / `dropped` / `failed` / `reason`）。

**手机端不需要改**（局域网仍走 HTTP）。若想让 App 在公网也能看，
可再加一个"云模式"数据源（MQTT over WebSocket，或直接拉云平台 API）。

**难点**：公网 broker 的鉴权与配额；各云平台主题规范不同（巴法云用 `uid` 作主题、
OneNET 有物模型）——这些只影响配置，不影响本项目代码。

## 2. 更丰富的本地交互（演示观感提升明显）

| 项 | 改动范围 | 说明 |
| --- | --- | --- |
| LCD 多页轮播 | `core/dispatcher.py` 的文案 + 加一个翻页计时 | 现有 LCD 只显示报警文案；可分页显示"心率/血氧"、"体温/室温"、"状态" |
| 按键翻页 + 消音键分离 | `sensors/button.py` 多实例 + `core` 里按键分派 | 现有按钮是"求救"；再加一个按键做翻页、一个做消音 |
| 呼吸灯 / 闪烁节奏按严重度分档 | `outputs/led.py`（已支持 blink）+ `dispatcher` | 警告=慢闪、紧急=快闪 |
| 语音播报个性化（称呼/时间） | `dispatcher.PRESENTATION_TABLE` | 例如"张奶奶，该吃药了"（固定时间提醒） |
| 定时提醒（吃药/喝水） | `core` 加一个"计划任务"表 + 规则引擎 | 属于产品功能扩展，实现简单、演示效果好 |

## 3. 数据与算法增强

| 方向 | 说明 | 风险 |
| --- | --- | --- |
| 趋势告警（而不只是阈值） | 例如"体温 2 小时内上升 1.2°C"；用 `store.py` 的历史数据算斜率 | 低；建议加在 `rules.py`，纯函数好测 |
| 睡眠质量评估 | 用 PIR 的夜间活动序列估算入睡/起夜/深睡时长 | 低（口径要在报告里写清是"估算"） |
| 跌倒检测升级 | 现在只有"久无活动"；可加 HC-SR04 测距（人离开床/地面距离突变）+ 加速度计 | **中高**（需要额外器件与更多调参） |
| 血氧算法标定 | 现有 `SpO2 = 104 - 17R` 是经验式，未与标准血氧仪对照 | 中（需要参照设备） |

## 4. 工程与交付质量（**答辩容易被问到的点**）

| 项 | 说明 |
| --- | --- |
| 系统自启动 + 看门狗 | 已提供 `rpi/deploy/health-monitor.service`；可再加 `WatchdogSec=` 与"进程崩溃自动重启"的演示 |
| 日志与留痕 | 现在用 `logging`；可加"按天滚动文件日志"（`RotatingFileHandler`），演示"出问题能查" |

| 手机端报警推送 | 现在靠轮询；可加 Android 前台服务 + 通知，实现"手机响铃" |
| 压测与长稳 | 连续跑 24 小时看内存/故障计数（`status()` 已提供计数），报告里放曲线很加分 |

## 5. 明确的"不做"清单（避免走偏）

- ❌ **不要**宣称医疗诊断结论（本项目是"看护提示"，报告与界面都要写清）。
- ❌ **不要**为了好看把"数据缺失"显示成 0 或"正常"（这是本项目的安全红线，见 `docs/02` §4）。
- ❌ **不要**把多个驱动塞进同一个文件（破坏"一人一文件"的协作前提）。
- ❌ **不要**在 `core/`、`net/` 里 import 具体驱动类（破坏分层，换器件就要改业务代码）。
- ❌ **不要**绕过硬件的物理限制（例如"用 MCP3002 读 MAX30102"——接口类型根本不匹配）。

## 6. 加新器件驱动的标准流程（十个器件之外还想加）

1. 在 `hal/registry.py` 的 `MANIFEST` 加一行（驱动名 → 模块:类），并在 `DRIVER_DOCS` 填负责人；
2. 照 `sensors/button.py` 写驱动（`open/read/close` + `describe` + 纯逻辑抽离）；
3. 在 `core/config.py` 的 `DEFAULT_CONFIG` 与 `rpi/config/devices.example.json` 加配置段；
4. 补单测（含"未 open 就 read 抛错"、"mock 不碰硬件"、"坏数据"三类）；
5. 跑 `python scripts/validate.py`（**引脚冲突检查会立刻告诉你有没有抢脚**）；
6. 若是新的**数据类型**，需要在 `core/rules.py` 与 `core/collector.py` 里接线
   （这一步属于契约扩展，请先读 `docs/CHANGELOG-接口.md` 并同步文档）。
