# 14 · 分步实施路线图（T0 → T13）：**一次只加一个元件**

> **这张表是给"动手的人"用的**：最终的交付物是完整监护系统，但**不一次性全插上**——
> 按 T0→T13 一级一级往上加，每级都留一份"能给别人看"的验收证据。
>
> **怎么用（三句话）**
> 1. **一次只动一个器件**：加新器件时，在 `rpi/config/devices.json` 里只打开它那一个 `enabled`，
>    其余保持上一级的状态；**能读通/能动作了再往下走**。
> 2. **每级都有独立判据**：一条命令 + 一个肉眼/耳朵能看到的现象 + 一份留档（JSON / 截图 / 读数）。
>    看不到那个现象就别进下一级——不然问题会叠在一起，分不清是哪一级引入的。
> 3. **每级做完就记两处**：`07-测试验收记录.md` 打勾；`13-真机接线现状与逐器件实测.md` 第 1 节记一行。
>
> **权威来源**（本文件不重复维护状态，避免"多处台账各说一套"）：
> - 引脚/地址：`hardware/01-引脚分配表.md` + `rpi/config/devices.json`（代码里 `hal/pins.py` 是单一来源）
> - 真机到底通了什么：**`13-真机接线现状与逐器件实测.md`**（唯一现状来源）
> - 验收填表：`07-测试验收记录.md`（54 项，填完就是报告里的表）
> - 每个器件的接线/寄存器/验收判据：`手册/03-器件任务书.md`

## 1. 每一级都要做的三件事（横切纪律）

```bash
cd ~/raspberry-health-monitor/rpi

# ① 代码侧不许退（不需要硬件，任何时候都能跑）
python3 scripts/validate.py                 # 11 项：含引脚冲突 / 文档一致性 / 640 项单测 / 基础版

# ② 只打开本级要用的器件（改 config/devices.json 的 enabled，一次只改一个）
python3 -m health_monitor drivers           # 确认驱动名与参数名
python3 -m health_monitor selfcheck --real  # 逐器件体检（⚠️ 按**设备名**遍历，见 ERROR.md E36）

# ③ 真机验收 + 留证（--skip-output 不发声不闪灯；--only 只验本级新加的器件）
python3 scripts/hardware_test.py --list                                  # 查设备名
sudo python3 scripts/hardware_test.py --yes --skip-output --only <本级设备名> --json <本级的报告文件名>
```

- **`--only` 会连前置检查一起收窄**：只验 DHT11 时不会因为"还没接 I2C 器件"而报错——
  阶梯式推进最怕的就是"满屏都是还没接的东西造成的失败"，那会把本级真正的信息埋掉。
- **留证三件套**：那份 JSON 报告 + 一张现场照片/截图（屏/灯/接线）+ `docs/07` 打勾。
- **卡住了先做"拔线对照"**：把本级的器件**拔掉**再跑一次上一级的验收——
  上一级恢复 ⇒ 问题在本级引入（线/器件/配置）；上一级也坏 ⇒ 是你动到了公共的东西（电源/地/总线）。
- ⚠️ 验收命令在中文 Windows 上跑也没问题（打印编码已加固，见 `ERROR.md` E41）。

### 1.1 ★★ 需要"人看/人听"的环节：**两段式**（2026-09-26 用户两次纠正后定为硬约定）

点灯、闪灯、鸣叫、按按键、拔插线这类动作，**效果只存在于人的感官里**，所以：

1. **先只说清预期**（我要做什么 → 你该看到/听到什么 → 大概多久），然后**停下**；
2. **等用户明确发话**（"开始"/"可以"）之后，**才**发命令执行；
3. 执行完用**选择题**问结果，并且**必须有"没看到/没注意"这个选项**。

用户原话："**你下次直接停下来，我发话你再开始**"。
`output_probe.py` 的 `--delay`（倒数）与 `--repeat`（两轮）只是**减震**，
**不能替代许可**——倒数只是把"抢时间"变成"抢 8 秒"。判据：

> **凡动作的效果只存在于人的感官里，许可权就在用户手上，不在代理手上。**
> 代理能做的只有三件：**说清预期 → 等许可 → 问结果**。

| --- | --- |
| 目标 | **先证明"ADC 本身能读"，再接传感器**——否则"读不到"分不清是 ADC 还是 TMP36 |
| 为什么必须 ADC | **树莓派没有任何模拟输入引脚**：TMP36 这类模拟输出器件**必须**经 ADC（课程重点） |
| 接线 | VDD/VREF → 脚 1（3.3V）、VSS → 脚 6、CLK → 脚 23、D_IN → 脚 19、D_OUT → 脚 21、CS/SHDN → 脚 24（**CE0**） |
| 自证接法 | CH0 → 3.3V、CH1 → GND（读数应分别贴近满量程与 0） |
| 验收 | `python3 scripts/diag_pin_levels.py --adc` ⇒ 两通道读出**明显不同**且与"接 3.3V / 接 GND"一致（±1 LSB ≈ 3.2 mV） |
| 常见坑 | CS 与 TFT 的 CE1 混淆（MCP3002 用 **CE0**、TFT 用 **CE1**）；SPI 没开；通道号与接线不一致 |
| 知识点 | SPI 时序、10 位 ADC、参考电压 |
| 卡住看 | `手册/03-器件任务书.md` §2.1、`05-排错手册.md` C 类（SPI） |

### T6 · 精密体温：TMP36 → MCP3002 CH0

| 项 | 内容 |
| --- | --- |
| 目标 | 比 DHT11（1 ℃ 分辨率）更细的体温：**10 mV/℃、25 ℃ = 750 mV** |
| 接线 | TMP36：左 `+Vs` → 脚 1（3.3V）、中 `VOUT` → MCP3002 **CH0**、右 `GND` → 脚 6 |
| 配置 | `body_temp`（`tmp36`, channel 0, vref 3.3, `calibration_offset_c`） |
| 验收 ① | 室温下 `body_temp_c` 落在 24~28 ℃（手指捏住 TMP36 应升到 30 ℃+） |
| 验收 ② | ADC 原始值 200~300（对应 0.75 V 左右）；与 DHT11 的室温**同趋势**（两路互相印证） |
| 验收 ③ | 临时把 `body_temp_max` 调到 30 ⇒ 触发 `ALARM: TEMP HIGH`（顺便验 T2 的报警链路也能被体温驱动） |
| 证据 | 两路温度同框截图（TMP36 与 DHT11）+ 原始 ADC 值 |
| 常见坑 | **方向接反**（+Vs/GND 反了读数乱跳）；CH0/CH1 搞混；**裸 SOT-23 封装插不上面包板**（需转接板）；读数偏高一点可用 `calibration_offset_c` 单点标定 |
| 知识点 | 电压→温度换算链路、单点标定、"原始值也要留档" |
| 卡住看 | `手册/03-器件任务书.md` §2.2（含换算推导）、`docs/13`（CH0≈1.95 V 的异常记录） |

### T7 · 生命体征：MAX30102（心率血氧）——**最难的一级**

| 项 | 内容 |
| --- | --- |
| 目标 | 手指一放，读出**心率**与**血氧**；手指拿开要如实显示"请将手指放好"（不是 0） |
| 接线 | VIN → 脚 1（3.3V）、GND → 脚 6、SDA → 脚 3、SCL → 脚 5（**与 LCD 共 I2C 总线**，地址不冲突） |
| 配置 | `vitals`（`max30102`, `address: 87` = **十进制** 0x57, `led_current: 7.6mA`） |
| 验收 ① | 手指贴住静置 10 秒 ⇒ `heart_rate_bpm` 55~100、`spo2_percent` 95~100、`finger_detected=true` |
| 验收 ② | 手指移开 ⇒ `finger_detected=false`，手机/接口显示 `--`，**绝不显示 0** |
| 验收 ③ | 心率稳定（同一姿势连读 3 次，波动 <±5 bpm） |
| ⚠️ 器件现状 | 本机这块 **Part ID(0x21) 读回 `0x00`**（应为 `0x15`）⇒ 先用 `python3 scripts/diag_hw_deep.py` + 看模块丝印确认型号；若是不兼容的兼容片，按 `drivers` 说明处理 |
| 常见坑 | 手指压太紧/太松都会失败；强环境光干扰；器件供电不足；FIFO 没清干净 ⇒ 读数跳 |
| 知识点 | I2C 寄存器读写、FIFO、纯算法（PPG 峰检测；算法已用合成波形单测） |
| 卡住看 | `手册/03-器件任务书.md` §1.1、`ERROR.md`（MAX30102 相关） |

## 3. 怎么判断"这一级真的过了"

> 三级判据，缺一不可（这也是本项目一直在用的口径）：

1. **代码侧**：`python3 scripts/validate.py` 11 项全 PASS（不含硬件）；
2. **真机侧**：`hardware_test.py` 里**该器件那一行**是"读到合理值 / 人工确认通过"，
   并且**拔掉它以后上一级仍正常**（证明本级没弄坏公共部分）；
3. **证据侧**：`docs/07` 那一行填了"实测通过 + 实测数据"，`docs/13` §1 记了一行当次结论。

### ⚠️ 最容易犯的三个错（本项目真实发生过）

| 错法 | 正确做法 |
| --- | --- |
| 把"单测通过"写成"真机通过" | 单测只证明**代码逻辑**；接线/地址/时序只能真机证明（`docs/07` 分了 T 与 H 两张表就是这个原因） |
| 把"曾经实测可用"当成"现在还通" | **接线会被人手动过**：2026-09-25 21:14 还能连采 111 个样本，22:05 复测就变成"数据线被拉死到地" ⇒ 每次上电重跑验收 |
| 一次插好几个器件再一起调 | **一次只加一个**：出问题时拔掉本级器件、回到上一级验收，就能立刻定位是不是本级引入的 |

> ✅ **`hardware_test.py` 已支持"只验一个器件"**（2026-09-26 加，正是为这张阶梯表加的）：
>
> ```bash
> python3 scripts/hardware_test.py --list                    # 查设备名
> sudo python3 scripts/hardware_test.py --only ambient       # 只验 DHT11 这一级
> sudo python3 scripts/hardware_test.py --only ambient,display
> sudo python3 scripts/hardware_test.py --exclude speaker
> ```
>

> 名字写错、或点名了 `enabled=false` 的器件，都会**明确报错**而不是"什么都没查却全绿"。
> 若某器件本来就没有数值判据（如 `tft` 要用 `tft_check.py`），报告末尾会有 **"检查覆盖"警告**提醒你。

## 5. 怎么"回到某一级"（**每级配置快照**，2026-09-26 与用户确认）

**代码只有一份**（`rpi/health_monitor/`）—— 级与级之间的差别只是**接线**和**开了哪些器件**。
所以"每一级可复现"靠的是**配置快照**，不是复制代码（复制 13 份会让一次 bug 修复要改 13 处、
并且必然互相漂移；今天的 E42/E44 都是"修一次、所有级受益"）。

* **快照在哪**：`rpi/config/stages.json` —— **"每一级开哪些器件"的单一来源**
  （每级记 `title` / `devices` / `status`（`verified` | `planned`）/ `verified_on` / `commit` / `note`）。
* **一键按某一级起服务**：

  ```bash
  cd ~/raspberry-health-monitor/rpi
  python3 scripts/stage_run.py --list-stages          # 看所有级与状态（[已验] / [计划]）
  python3 scripts/stage_run.py --stage T2             # 只开 T2 的器件起服务（临时改配置）
  python3 scripts/stage_run.py --stage T2 --port 8091 # 撞端口时换一个
  python3 scripts/stage_run.py --stop                 # 停服务 + 还原配置
  ```

* **想看"那一级当时的样子"**：按该级快照里的 `commit` 回看即可
  （T1 = `7f17f53`、T2 = `ba6ae30`；`git show <commit> --stat` 看改了什么）。
* **快照有机器守卫**（`tests/scripts/test_stage_run.py::TestStageSnapshots`）：
  结构完整、器件名必须真实存在、`verified` 必须留日期、**级别单调递增**（后一级只能多开、不能少开）、
  T0 必须写明"走 `basic/`"。
* ⚠️ 用户没让打 tag，所以**没有** `stage-Tn` 这类标签；要回到某一级就用"快照 + commit"。
