## 1. 项目定位（答辩第一句话就该说清）

> "这是一个**居家老人健康与安全监护系统**：树莓派 5 作为**边缘节点**，
> 采集心率血氧、体温、环境温湿度与人体活动，在**本地完成判定与声光报警**（断网也能工作），
> 并通过 HTTP 把数据与报警推给子女的**安卓 App**；数据同时落本地历史库。
> 架构上是**端 — 边 — 云**三层。"

**必须主动说明的边界**（老师一定会问）：

- 本系统是**看护提示工具，不是医疗设备**，不做医学诊断；
- 心率血氧来自 MAX30102 的光电容积脉搏波（PPG），**未与标准医疗器械对照标定**；
- 报警阈值是**工程经验默认值**，可配置。

## 6. 答辩结构建议（10 分钟版）

1. **场景与痛点**（1 分钟）：老龄化 / 独居老人 / 跌倒与突发疾病无人知晓。
2. **系统总览**（1 分钟）：贴 README 里那张架构图，讲"端-边-云"。
3. **硬件与接线**（2 分钟）：哪些总线（I2C / SPI / 单总线 / GPIO）、为什么需要 ADC、
   为什么 MAX30102 不能接 ADC（**这一问几乎必被问**）。
4. **软件设计**（2 分钟）：HAL 契约 + 6 个驱动 + 报警规则引擎（迟滞/冷却/恢复）。
5. **现场演示**（2 分钟）：`python -m health_monitor demo`，或用真机 + 手机 App。
6. **难点与取舍**（1 分钟）：
   - "数据缺失"绝不当作"正常"（陈旧保护、`null` 语义）；
   - 报警不刷屏（冷却 + 迟滞）；
   - 团队并行开发的契约设计（一人一驱动、业务层不认识具体器件）。
7. **边界与展望**（1 分钟）：非医疗诊断；可上云 / 可加跌倒检测。

**预演问题清单**（每组至少练一遍）：

- 树莓派没有模拟引脚，模拟传感器怎么办？（答：MCP3002 ADC，讲 SPI 时序与控制字）
- 为什么心率读不到时显示"未知"而不是 0？（答：0 会被规则判成"心率过低"误报）
- 断网了还能报警吗？（答：能，规则引擎与声光在本地；手机端只是远程查看）
- 阈值能不能改？怎么改？（答：`config/devices.json` 的 `thresholds`，改完重启）
- 你们的系统会不会误报？（答：讲迟滞 + 冷却 + 手指检测 + 陈旧保护四条）
- 队友之间怎么保证代码不打架？（答：HAL 契约 + 一人一文件 + 契约测试 + validate 脚本）

## 7. 风险与应对

| 风险 | 概率 | 应对 |
| --- | --- | --- |
| 某器件调不通（I2C 无应答 / 时序不对） | 高 | 先用 mock 跑通业务（不影响其他人）；真机上按 `DeviceInitError` 里的线索排查（`i2cdetect -y 1`、`ls /dev/spidev0.*`） |
| 器件损坏/缺件（如 TMP36 是裸 SOT-23） | 中 | 备选：换电位器走 ADC 通道；把该器件 `enabled: false`，系统仍可运行 |
| 蓝牙音箱配对不上 | 中 | 先用有线音箱/HDMI 出声验证 TTS 链路，最后再调蓝牙 |
| 树莓派 5 的 GPIO 库不兼容 | 中 | 本项目已明确用 `gpiozero + lgpio`（`RPi.GPIO` 在 Pi 5 上不可用），文档已写 |
| 进度落后 | 中 | 优先保"核心链路"（心率 + 体温 + 活动 + 报警 + 手机查看），拓展件（HC-SR04）最后做 |
