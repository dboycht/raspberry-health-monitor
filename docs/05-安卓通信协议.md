# 安卓端通信协议（树莓派 ↔ 手机）

> 本文件是**手机端开发的唯一接口依据**。树莓派端实现见
> `rpi/health_monitor/net/web.py`；两边任何一方改动接口，都必须同步更新本文件。

## 1. 总体架构

```
┌─────────────┐   HTTP/JSON（局域网，家庭 WiFi）   ┌──────────────────────┐
│ Android App │ ────────────────────────────────► │ 树莓派 5 后端服务      │
│ （监护端）   │ ◄──────────────────────────────── │  health_monitor serve │
└─────────────┘        轮询 3~5 秒                └──────────────────────┘
                                                            │
                                            传感器（MAX30102 / DHT11 / TMP36
                                            / HC-SR501）+ LCD + 音箱 + 蜂鸣器 + LED
```

- **通信方式**：HTTP/JSON，**轮询**（3~5 秒一次足够；本项目数据变化慢，不需要 WebSocket）。
- **地址**：`http://<树莓派局域网IP>:8080`（树莓派上用 `hostname -I` 查 IP）。
- **为什么不用 MQTT**：局域网直连最简单、断网可自愈、无需第三方云账号；
  若课程要求"上云"，可在树莓派端再加一个 MQTT 发布器（见 `docs/07-拓展与上云.md`），
  手机端不需要改。

## 2. 通用约定

| 项 | 约定 |
| --- | --- |
| 编码 | 请求与响应均为 **UTF-8** |
| 请求体 | 本协议**不使用请求体**，参数一律走 query string（服务器不读 body） |
| 鉴权 | 默认无鉴权；服务器配置了 `--token` 时，**每个请求**都要带请求头 `X-Auth-Token: <token>`，否则返回 401 |
| 时间 | 所有时间戳为 **Unix 秒（float，UTC）**；手机端负责转本地时间显示 |
| 数值缺失 | **一律是 JSON `null`，绝不是 0**；手机端必须显示"未知/--"，**不得显示 0**（0 bpm 会吓到人） |
| 错误格式 | 非 2xx 时返回 `{"ok": false, "error": "<原因>"}` |

## 3. 接口一览

| 方法 | 路径 | 用途 | 手机端建议刷新频率 |
| --- | --- | --- | --- |
| GET | `/api/v1/health` | 系统健康 + 每个设备状态 | 10 秒 |
| GET | `/api/v1/current` | **当前读数**（首页主数据） | 3~5 秒 |
| GET | `/api/v1/history` | 历史曲线数据 | 进详情页时拉一次 |
| GET | `/api/v1/alarms` | 报警事件（实时 + 历史） | 5 秒（或报警页） |
| GET | `/api/v1/devices` | 设备清单与接线说明 | 设置页进一次 |
| POST | `/api/v1/silence` | 消音 | 用户点击 |
| POST | `/api/v1/sos` | 触发紧急求助 | 用户点击 |
| POST | `/api/v1/speak` | 让音箱说话（调试） | 用户点击 |

## 4. 接口详情

### 4.1 `GET /api/v1/current` —— 当前读数（最重要）

```json
{
  "ok": true,
  "data": {
    "ts": 1790001600.5,
    "heart_rate_bpm": 72.4,
    "spo2_percent": 97.9,
    "finger_detected": true,
    "vitals_quality": 0.95,
    "body_temp_c": 36.5,
    "ambient_temp_c": 24.5,
    "humidity_percent": 55.2,
    "motion_state": "detected",
    "motion_silent_s": 0.0,
    "sensor_failures": {},
    "data_age_s": 0.4,
    "data_stale": false
  },
  "active_alarms": {}
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ts` | number | 本次快照时间（Unix 秒） |
| `heart_rate_bpm` | number \| **null** | 心率。`finger_detected=false` 或算法未收敛时为 `null` |
| `spo2_percent` | number \| null | 血氧饱和度 % |
| `finger_detected` | boolean \| null | 是否检测到手指/皮肤贴合；`null` 表示该数据源不可用 |
| `vitals_quality` | number \| null | 数据质量 0~1 |
| `body_temp_c` | number \| null | 精密体温（TMP36 + MCP3002） |
| `ambient_temp_c` | number \| null | 室温（DHT11） |
| `humidity_percent` | number \| null | 湿度（DHT11） |
| `motion_state` | `"detected"` \| `"idle"` \| `"unknown"` \| null | 人体活动状态 |
| `motion_silent_s` | number \| null | 距上次检测到人的秒数（`null`=无法判断） |
| `sensor_failures` | object | `{设备名: 连续失败次数}`，空对象表示全部正常 |
| `data_age_s` | number \| **null** | 距"最近一次成功读到新数据"的秒数；`null` = 从未读到过 |
| `data_stale` | boolean | 快照是否已经**不值得相信**（`data_age_s` 超过阈值，或从未读到过数据） |
| `active_alarms` | object | `{报警码: 首次触发时间}`，空对象表示当前无报警 |

**手机端渲染规则（硬要求）**：

- `null` → 显示 `--` 或"未知"，**绝不显示 `0`**；
- `finger_detected == false` → 心率/血氧区域显示"请将手指放好"，不要显示 0；
- `sensor_failures` 非空 → 在界面上以**警告色**列出"X 传感器异常（连续 N 次）"；
- **`data_stale == true`** → 顶部/卡片区显示"数据可能已过期（最近 X 秒无新数据）"。
  这条与"请求失败"是**两件事**：请求可能成功（服务活着），但树莓派那边的传感器早就没数据了；
- `motion_state == "unknown"` → 显示"未知"，**不要**推断成"无人"。

### 4.2 `GET /api/v1/health` —— 系统健康

```json
{
  "ok": true,
  "ts": 1790001600.5,
  "uptime_s": 612.3,
  "version": "1.0.1",
  "mock": false,
  "active_alarms": {"hr_too_high": 1790001500.0},
  "dispatcher": {"enabled": true, "outputs": ["alarm_buzzer", "display", "speaker", "status_led"],
                 "dispatched": 4, "errors": [], "silenced_until": 0.0},
  "devices": {
    "vitals": {
      "driver": "max30102", "interval_s": 1.0, "reads": 612, "failures": 0,
      "last_error": null, "stale": false, "last_ok_age_s": 0.4, "optional": false,
      "device_status": {"name": "vitals", "kind": "vital", "opened": true, "mock": false,
                        "read_count": 612, "fault_count": 0, "last_error": null}
    }
  }
}
```

用途：手机端"设置/关于"页显示树莓派在线状态、版本号、各传感器是否正常。

### 4.3 `GET /api/v1/history` —— 历史曲线

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `metric` | `ambient_temp_c` | 指标名：`ambient_temp_c` / `humidity_percent` / `body_temp_c` / `motion` / `vitals`（心率血氧一起返回） |
| `limit` | 120 | 返回条数（1~2000） |
| `since` | 无 | 起始 Unix 秒 |

响应：

```json
{"ok": true, "metric": "ambient_temp_c", "count": 3,
 "data": [{"ts": 1790001500.0, "value": 24.4, "ok": 1, "device": "ambient"},
          {"ts": 1790001510.0, "value": 24.5, "ok": 1, "device": "ambient"}]}
```

`metric=vitals` 时元素形如：`{"ts":…, "heart_rate_bpm":72.4, "spo2_percent":97.9, "finger_detected":1, "quality":0.95}`
（`finger_detected=0` 时两个数值字段为 `null`）。

### 4.4 `GET /api/v1/alarms` —— 报警事件

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `limit` | 50 | 返回条数（1~500） |

```json
{"ok": true,
 "live": [{"ts": 1790001560.0, "code": "hr_too_high", "severity": 2,
           "light": "yellow", "blink": true, "speak": "心率偏高，请注意休息",
           "beep_times": 3, "silenced": false}],
 "history": [{"ts": 1790001560.0, "code": "hr_too_high", "severity": 2,
              "message": "心率偏高 128.4bpm，请注意查看", "value": 128.4, "unit": "bpm",
              "source": "vitals", "detail": {}, "pushed": 0}]}
```

- `live`：本次运行中**实际下发过**的报警（含"消音"标记），用于"刚才发生了什么"；
- `history`：落库的报警记录（重启后仍在），用于事件列表。

**报警码与中文名对照**（手机端请照此表显示；新增码必须双方同步）：

| code | 中文 | 默认严重度 |
| --- | --- | --- |
| `hr_too_high` / `hr_too_low` | 心率过高 / 过低 | 2 警告 |
| `spo2_too_low` | 血氧过低 | 3 紧急 |
| `body_temp_high` / `body_temp_low` | 体温偏高 / 偏低 | 2 |
| `ambient_temp_high` / `ambient_temp_low` | 室温偏高 / 偏低 | 1 提示 |
| `humidity_high` | 湿度过高 | 1 |
| `no_motion_too_long` | 长时间无活动（疑似跌倒） | 3 |
| `night_frequent_wake` | 夜间频繁起夜 | 2 |
| `sos_pressed` | 紧急求助 | 3 |
| `sensor_fault` | 传感器故障 | 2 |
| `device_offline` | 设备离线 | 2 |
| `all_clear` | 已恢复正常 | 0 |

严重度：`0=正常`、`1=提示`、`2=警告`、`3=紧急`（可直接比大小）。

### 4.5 `GET /api/v1/devices` —— 设备清单与接线

```json
{"ok": true, "devices": {"vitals": {"driver": "max30102", "interval_s": 1.0,
  "describe": {"name":"vitals","kind":"vital","mock":false,"bus":"I2C-1",
               "pins":{"sda":"GPIO2 / 物理脚 3","scl":"GPIO3 / 物理脚 5"},"notes":"I2C 0x57"}}}}
```

用途：手机端"硬件"页展示接线说明；也可当作**答辩演示**的"系统自述"。

### 4.6 `POST /api/v1/silence` —— 消音

无参数。返回：

```json
{"ok": true, "silenced_until": 1790001900.0}
```

语义：在 `silenced_until` 之前，树莓派**只亮灯与更新显示，不响铃、不播报**。
⚠️ 手机端**不要**把消音当成"解除报警"——报警态仍然存在，`active_alarms` 不会因此清空。

### 4.7 `POST /api/v1/sos` —— 紧急求助

无参数。返回被触发的报警事件：

```json
{"ok": true, "event": {"ts": 1790001560.0, "code": "sos_pressed", "severity": 3,
  "message": "已收到紧急求助，请立即查看", "value": null, "unit": "", "source": "sos", "detail": {}}}
```

语义：会**先解除静音**再报警（求救必须能响），并在树莓派本地触发蜂鸣 + 语音 + 红灯 + LCD。

### 4.8 `POST /api/v1/speak` —— 让音箱说话（调试用）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 中文短句，**最多 60 字**（超长返回 400，避免播报没完没了） |

```json
{"ok": true, "sent_to": 1, "text": "老人请注意休息"}
```

## 5. 手机端实现要点（给安卓同学）

1. **轮询而不是长连接**：`/current` 3~5 秒一次；在 `onStop()` 里停掉轮询（省电，也避免后台被系统杀）。
2. **断网可恢复**：请求失败不要弹崩溃对话框，显示"连接中…"并保留上次数据（标注"数据可能已过期"）。
3. **首屏必须先连一次 `/health`**：确认版本与在线状态，避免"连上了但服务没跑"。
4. **数值缺失的渲染规则**（见 §4.1）是**硬要求**：`null` 不能显示为 0。
5. **求助按钮要防误触**：建议长按 1.5 秒触发 `/sos`，并在触发后给出明显的确认反馈。
6. **Android 网络权限**：`AndroidManifest.xml` 需要 `INTERNET` 权限。
7. **明文 HTTP**：局域网 IP 是明文 http，Android 9+ 需要在
   `res/xml/network_security_config.xml` 里允许明文（或把目标域名/IP 加白名单），
   否则请求会被系统直接拒绝（`CLEARTEXT communication not permitted`）。
   详见 `docs/06-安卓开发指南.md`。

## 6. 兼容与变更纪律

- 本文档与 `rpi/health_monitor/net/web.py` 必须**成对修改**；只改一边算缺陷。
- 新增字段是**兼容**的（手机端应忽略不认识的字段）；
  删除字段、改字段含义、改报警码字符串都是**破坏性变更**，必须同步更新本文档与手机端。
- 服务器版本可从 `/api/v1/health` 的 `version` 读取；手机端应在"关于"页显示，
  方便排查"手机端与树莓派版本不一致"的问题。
