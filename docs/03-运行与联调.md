# 03 · 运行与联调（把系统跑起来 → 手机能看）

> **目标**：树莓派上正式运行监护服务；用浏览器看状态页；手机 App 连上并显示真实数据。
> **预计 30 分钟**。
> **做完的判据**：本文第 6 节 6 条勾完。

---

## 1. 先跑一遍"不接硬件也能跑"的演示（30 秒，确认代码没问题）

```bash
cd ~/raspberry-health-monitor/rpi
python3 -m health_monitor demo
```

预期：**11 幕**剧情依次打印（正常 → 心率高 → 血氧低 → 久无活动 → 求救 → 复位 → 传感器故障 → 恢复），
最后打印 `演示结束：... 下发失败 0 次`，退出码 0。

> 这一步**不碰任何硬件**（用内置模拟器件）。如果这一步就失败，说明是代码/环境问题，
> 不是接线问题——直接看 `05-排错手册.md`。

## 2. 真实硬件体检

```bash
python3 -m health_monitor selfcheck --real
```

预期：每个器件一行，`自检` 都是 `OK`。有 FAIL 的按提示修（它会打印排查线索）。

## 3. 正式启动服务

```bash
python3 -m health_monitor serve --real --port 8080
```

看到这样的输出就算起来了：

```
================================================================================
树莓派健康监护服务已启动（版本 1.0.1，mock=False）
  接口地址：http://<树莓派IP>:8080/api/v1/current
  健康检查：http://127.0.0.1:8080/api/v1/health
  设备数量：9（输入 4 / 输出 5）
  模式说明：真实硬件采集
  按 Ctrl+C 退出
================================================================================
```

**常用启动参数**：

| 参数 | 用途 |
| --- | --- |
| `--real` | 用真实硬件（不加就是模拟模式） |
| `--port 8080` | 换端口（端口冲突时用） |
| `--token <口令>` | 开启令牌校验（**别在公网裸奔**；见第 7 节） |
| `--quiet` | 不发声/不显示（只采集，适合夜里调试） |
| `--store /path/history.db` | 指定历史库位置 |

> 想让开机自启：`cd rpi/deploy && sudo bash install-service.sh`（它会自动改成你的路径）。

## 4. 看状态网页（答辩现场很实用）

在**电脑或手机浏览器**打开：

```
http://<树莓派IP>:8080/
```

（树莓派自己上也能看：`http://127.0.0.1:8080/`）

页面上应该有：状态横幅、六张指标卡（心率/血氧/体温/室温湿度/活动/数据年龄）、
当前报警、每个设备的读取次数与状态、最近 15 条报警。**每 5 秒自动刷新**。

**判据**：
- 数值在合理范围（心率 55~100、血氧 95~100、体温 35~38、室温 15~35）
- **不该出现 0**：读不到的项显示"未知"——这是刻意设计（见 `08-常见问答.md`）
- 手指拿开时，心率/血氧显示"请将手指放好"，而**不是 0**

**JSON 接口速查**（调试用）：

| 地址 | 看什么 |
| --- | --- |
| `/api/v1/current` | 当前读数（手机端就调它） |
| `/api/v1/health` | 每个设备状态 + 上云状态 |
| `/api/v1/alarms` | 报警事件 |
| `/api/v1/history?metric=ambient_temp_c&limit=120` | 历史曲线数据 |

命令行验证：

```bash
curl -s http://127.0.0.1:8080/api/v1/current | python3 -m json.tool
```

## 5. 手机 App 联调

### 5.1 装 APK

APK 在仓库里没有（构建产物不入库），两种拿法：

- **自己构建**（有 Android 环境的电脑）：见 [`手册/06-安卓开发指南.md`](手册/06-安卓开发指南.md)，
  产物在 `android/app/build/outputs/apk/debug/app-debug.apk`
- **让同学发你**：直接用他们构建好的 `app-debug.apk`（微信传文件即可）

安装：手机允许"安装未知来源应用" → 点开 APK 安装。

### 5.2 连树莓派

1. 手机和树莓派连**同一个 WiFi**
2. 打开 App → 设置页 → 填地址：`http://192.168.1.20:8080`
   （只填 `192.168.1.20` 也行，App 会自动补 `http://` 与 `:8080`）
3. 若树莓派启动时带了 `--token`，把令牌也填上
4. 点"测试连接"→ 应显示成功；回首页应看到真实数值

### 5.3 手机上要验的 4 件事

| 操作 | 期望 |
| --- | --- |
| 首页看数据 | 心率/血氧/体温/室温湿度/活动五张卡都是真实值（不是 `--`） |
| 手指拿开 | 心率区显示"请将手指放好"，**不显示 0** |
| 点"消音" | 树莓派蜂鸣器停响（期间仍亮灯） |
| **长按"求助"1.5 秒** | 树莓派响铃 + 红灯 + LCD 显示 `SOS!`，手机出现"求助已发送" |

> ⚠️ 长按不足 1.5 秒**不会**触发（防误触设计）；松手会取消。

### 5.4 连不上时按这三层查

| 层次 | 怎么查 | 期望 |
| --- | --- | --- |
| 网络可达 | 手机浏览器打开 `http://<树莓派IP>:8080/api/v1/health` | 返回 JSON |
| 服务在跑 | 树莓派上 `curl http://127.0.0.1:8080/api/v1/health` | 返回 JSON |
| 采集正常 | 返回里的 `devices.*.stale` / `failures` | `stale=false`、`failures=0` |

手机浏览器打得开、App 打不开 ⇒ 检查 App 里填的地址与端口；两边都打不开 ⇒ 服务或网络问题。

## 6. 报警闭环实测（**这一步最能拿分**）

逐个触发一次，确认"树莓派本机动作"与"手机端显示"都对：

| 触发方式 | 树莓派本机应有 | 手机端应有 |
| --- | --- | --- |
| 心率异常：快速搓手后立刻贴手指（或把配置里 `hr_max` 临时改到 60） | 黄灯闪 + 蜂鸣 3 声 + 语音"心率偏高" + LCD `ALARM: HR HIGH` | 红色横幅 + 事件列表出现该条 |
| 血氧过低：把 `spo2_min` 临时改到 99 | **红灯** + 蜂鸣 4 声 + 语音 | 紧急横幅 |
| 久无活动：把 `no_motion_timeout_s` 临时改到 30，然后人走开 | 红灯闪 + 蜂鸣 + 语音"长时间没有检测到活动" | 紧急横幅 |
| 紧急求助：按实体按键（或手机长按求助） | 蜂鸣 5 声 + 语音"已收到紧急求助" + LCD `SOS!` | 紧急横幅 |
| 传感器故障：拔掉 MAX30102 的 SDA 线 | 黄灯闪 + 语音"设备异常，请检查传感器接线" | 警告 + 设备状态里 `failures` 增长 |
| 恢复：把线插回 / 把阈值改回来 | 绿灯 + LCD `STATUS: NORMAL` | 横幅消失（收到 all_clear） |

> ⚠️ **改完阈值记得改回去**，并把 `devices.json` 恢复原样（或在报告里注明是临时改动）。

## 7. 安全与上线（选做，但建议看一眼）

- **只在家庭局域网用**：默认 `--host 0.0.0.0` 会在局域网内可访问。
- **不要直接暴露到公网**：真要做远程访问，至少：
  1. 加 `--token <长口令>`（所有请求必须带 `X-Auth-Token` 头）；
  2. 用内网穿透（frp / ZeroTier / Tailscale）而不是路由器端口映射；
  3. 改默认端口。
- 本系统的定位是**看护提示**，不是医疗设备——报告与答辩都要说这句。
