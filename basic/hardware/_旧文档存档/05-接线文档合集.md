## 接线总览（三根线速查 + 硬件判据）

> 这份目录是 `basic/` 的**硬件入口**：只讲一件事 —— 把 **DHT11 温湿度模块**接到树莓派 5 上，
> 让 `python3 run.py` 能读到真实温度与湿度。
> 软件怎么跑见 `../README.md`；验收怎么打勾见 `../验收说明.md`。

#### 0. 一句话接线（三根线）

| DHT11 侧 | 接到树莓派（物理脚） | BCM | 说明 |
| --- | :---: | --- | --- |
| VCC / + / VDD | **1** | — | **必须 3.3V**；不要接 5V（物理脚 2/4）——数据电平会被拉到 5V，伤 GPIO |
| GND / − | **6** | — | 任意一个 GND 脚都行（脚 6/9/14/20/25/30/34/39）；**必须共地** |
| DATA / OUT / S | **7** | GPIO4 | 单总线数据线（双向）；裸四针传感器必须外接 4.7kΩ~10kΩ 上拉到 3.3V |

> 记忆点：**供电 3.3V、数据 GPIO4（物理脚 7）、一定要共地**。

#### 2. 接线速查（本基础版用到的 3 个脚）

| 物理脚 | BCM | 用途 | 信号 | 建议线色 | 关键提醒 |
| :---: | --- | --- | --- | :---: | --- |
| **1** | — | VCC | 供电 | 红 | **必须 3.3V**；不要接 5V（物理脚 2/4）——数据电平会被拉到 5V，伤 GPIO |
| **6** | — | GND | 地 | 黑 | 任意一个 GND 脚都行（脚 6/9/14/20/25/30/34/39）；**必须共地** |

**其余 37 个脚本基础版全部空闲**（完整分配见 `01-引脚分配表.md`）。

#### 3. 三分钟接完的顺序

1. **断电**（拔掉树莓派电源；带电插拔是烧 GPIO 的头号原因）；

2. 红线上 **3.3V**（物理脚 1/17），黑线接 **GND**（物理脚 6 或任意地脚）；

3. 黄线接**数据脚 7（GPIO4）**；

4. 如果是**裸四针**传感器：在 DATA 与 3.3V 之间接一个 4.7kΩ~10kΩ 电阻（三针模块通常已自带，不用接）；

5. 上电，跑自检与采集：

```bash
cd ~/raspberry-health-monitor/basic
python3 tools/selfcheck.py            # 应看到"真硬件后端可用：lgpio"
python3 tools/diag_dht_line.py        # 三态电平判据（读不到数据时用它定位）
python3 run.py                        # 真实读数 + 动态曲线
```

| 3 | 数据线通 | 万用表蜂鸣档：模块 DATA ↔ **物理脚 7** | **响** |

| 内容 | 唯一来源 |
| --- | --- |
| BCM ↔ 物理脚映射 | `basic/pins.py` 的 `BCM_TO_PHYSICAL` |

## 接线图与逐线接续表（含万用表验证）

#### 1. 接线图（示意图，只画本基础版要接的三根线）

```
 树莓派 5 · 40-pin（俯视，只画要接的三个脚）  DHT11 模块端子

 脚  1★ 3.3V     ──────────●   VCC           （红线）

 脚  6★ GND      ──────────●   GND           （黑线）

 脚  7★ GPIO4    ──────────●   DATA          （黄线）

  ① 三个物理脚：1（3.3V）、6（GND）、7（GPIO4）　★ = 本基础版用到的脚（其余 37 个空闲）
  ② 裸四针传感器：在 DATA 与 3.3V 之间接一个 4.7kΩ~10kΩ 上拉电阻（三针模块通常已自带）
  ③ 颜色只是约定：红线=电源、黑线=地、黄线=数据（换色可以，但要在验收记录里写明）
  ④ DHT11 模块丝印可能是 VCC/DATA/GND，也可能是 + / out / −（对应关系见下面的逐线表）
```

> 三针**模块**（带小板的成品）通常已经焊好上拉电阻，**不用自己再接**；
> 四针**裸传感器**（光板一个元件）必须外接 4.7kΩ~10kΩ 上拉，否则永远读不到（一直 NaN / 无应答）。

#### 2. 逐线接续表（照这个插，一根都别猜）

| 信号 | DHT11 侧丝印 | 树莓派物理脚 | BCM | 建议线色 | 关键提醒 |
| --- | --- | :---: | --- | :---: | --- |
| 供电 | `VCC / + / VDD` | **1** | — | 红 | **必须 3.3V**；不要接 5V（物理脚 2/4）——数据电平会被拉到 5V，伤 GPIO |
| 地 | `GND / −` | **6** | — | 黑 | 任意一个 GND 脚都行（脚 6/9/14/20/25/30/34/39）；**必须共地** |
| 数据 | `DATA / OUT / S` | **7** | GPIO4 | 黄 | 单总线数据线（双向）；裸四针传感器必须外接 4.7kΩ~10kΩ 上拉到 3.3V |


**接线顺序**：先电源 → 再地 → 最后信号。每插一根就检查一次有没有插错列。

#### 3. 三种封装的差别（买到的可能是哪一种）

| 封装 | 长相 | 需要上拉吗 | 供电 |
| --- | --- | --- | --- |
| **三针模块** | 小板 + 3 个排针，丝印 `VCC/DATA/GND` 或 `+ / out / -` | **不需要**（板上已有） | 3.3V（**见第 4 节**） |
| **四针裸传感器** | 光秃秃一个蓝色/白色元件，4 个长脚 | **需要** 4.7kΩ~10kΩ | 3.3V（脚 1 或 17） |
| **AM2302 / DHT22** | 白色塑料壳，3 或 4 脚 | 模块版已自带 | 3.3V |

> 本基础版的代码对 DHT11 / DHT22 都适用（都是"单总线、40 bit、校验和"），
> 只是量程判据按 DHT11 写死（0~50℃ / 20~90%RH）。

#### 4. 供电为什么必须 3.3V（**本基础版最容易被坑的一点**）

| 事实 | 说明 |
| --- | --- |
| 数据线电平 = 模块供电电压 | DHT11 的 DATA 是**开漏/上拉**结构。模块接 5V 时，上拉把 DATA 拉到 **5V**；树莓派 GPIO 只耐受 **3.3V** |
| 后果 | 轻则读数不稳、重则**永久损坏 GPIO**（甚至整块板） |
| 有些模块丝印写 5V | 指的是 **AM2302 那种带稳压的模块**（板上有 3.3V LDO）。**DHT11 不要接 5V** |
| 本基础上的做法 | 供电一律走 **3.3V（物理脚 1/17）**，5V（脚 2/4）本基础版**不接任何东西** |

**判据（可执行）**：上电后万用表量模块 `VCC` 对 `GND`，必须是 **约 3.3V**；
若量到 5V，立刻断电改线（这是"接线错误"里唯一会烧硬件的错）。

#### 5. 接完怎么验（万用表 + 脚本，两套判据都要过）

##### 5.1 断电量电阻（防短路，30 秒）

| 量哪里 | 档位 | 期望 | 不对说明什么 |
| --- | --- | --- | --- |
| 3.3V ↔ GND（树莓派这侧，**模块先拔掉**） | 电阻档 | 不导通（或读数很大） | 导通 = 电源短路，**绝对不能上电** |
| 模块 DATA ↔ 树莓派物理脚 7 | 蜂鸣档 | 响 | 不响 = 线插错列/断了 |
| 模块 GND ↔ 树莓派 GND 脚 | 蜂鸣档 | 响 | 不响 = 没共地（读数必然乱跳） |
| 模块 DATA ↔ 3.3V（裸传感器） | 电阻档 | 约 4.7kΩ~10kΩ | 无穷大 = 上拉没接 |

##### 5.2 上电量电压（判断器件有没有工作）

| 量哪里 | 期望 | 不对时的含义 |
| --- | --- | --- |
| 模块 VCC ↔ GND | **约 3.3V** | 0V = 没供上电；5V = 接错到 5V 脚（危险） |
| DATA ↔ GND（空闲时） | **约 3.3V**（高（约 3.3V）） | 0V = 线被拉死/接错；乱跳 = 没接上/接触不良 |

##### 5.3 脚本判据（`basic/tools/diag_dht_line.py`）

```bash
cd ~/raspberry-health-monitor/basic
python3 tools/diag_dht_line.py            # 三态电平（上拉/下拉/浮空 各读 50 次）
python3 tools/diag_dht_line.py --read 5   # 顺便连读 5 次，看真实应答
```

它会把"上拉=1、下拉=0"这类组合翻译成结论（**哪一种组合对应哪种故障**），
不要求你看懂寄存器。

##### 5.4 最终判据（读得到数才算通）

```bash
python3 run.py --no-plot --duration 20    # 20 秒，只采集与存档
python3 run.py                            # 真实读数 + 动态曲线窗口
```

| 期望 | 说明 |
| --- | --- |
| 终端每行都是真实数值（如 `温度: 25.0 ℃，湿度: 58 %`） | 这才是"通了" |
| 温度落在 0~50℃、湿度落在 20~90%RH | 超出量程说明器件/接线有问题 |
| 采样间隔 ≥3 秒（默认） | DHT11 两次读取必须间隔 ≥2 秒，否则返回陈旧数据 |

#### 6. 现象 → 原因对照（按现象查）

| 现象 | 最可能的原因 | 下一步 |
| --- | --- | --- |
| `只捕获到 0 个边沿：传感器没有应答` | 没供电 / 数据线插错列 / 没共地 / 裸传感器缺上拉 | 先量 VCC 是否 3.3V，再跑 `diag_dht_line.py` |
| `校验和不符` | 线太长、接触不良、电源噪声、读取太快 | 缩短杜邦线、换线、确认间隔 ≥2 秒 |
| 每次都是"未知" | DATA 接到别的脚（不是物理脚 7） | 蜂鸣档量 DATA ↔ 脚 7 |
| 读数偶尔对、偶尔乱 | 面包板接触不良 / 电源轨与信号插在同一列 | 换孔重插；面包板**每一列纵向导通**，别把电源和信号插同列 |
| 中文变方框（曲线窗口） | 缺中文字体 | `sudo apt install -y fonts-noto-cjk` |
| `没有可用的 DHT11 读取后端` | 没装 lgpio，或是在电脑上跑 | `sudo apt install -y python3-lgpio`；电脑上用 `--mock` |

> 完整"现象 → 原因"还包括软件侧的（中文方框、matplotlib 缺失等），见 `../README.md` 第 7 节。

## 供电与安全

> 这一页只有 6 条规矩，但**每一条都对应一次真实的硬件损坏或一周的排查**。
> 本基础版只接一个 DHT11，风险很低 —— 但"以后加器件"时请回来重读第 5 节。

#### 1. 六条红线（照做）

| # | 规矩 | 为什么 |
| --- | --- | --- |
| 1 | **插拔任何杜邦线之前先断电**（拔电源，或 `sudo poweroff` 后等绿灯灭） | 带电插拔最容易把 5V 蹭到 GPIO 上；热插拔还可能损坏 SD 卡上的文件系统 |
| 2 | **DHT11 供 3.3V，绝不接 5V** | 数据电平会跟着供电变成 5V，超出 GPIO 耐压（见 `02-接线图.md` 第 4 节） |
| 3 | **所有器件必须与树莓派共地** | 不共地的典型症状：读数乱跳、时通时不通 |
| 4 | **不要用 40-pin 的 5V 脚给 3.3V 器件供电**（脚 2、4） | 本基础版**一个 5V 器件都没有**，那两脚直接空着 |
| 5 | **上电前先量电源对地有没有短路** | 30 秒的检查能避免烧板（方法见 `02-接线图.md` 第 5.1 节） |
| 6 | **手摸板子前先摸一下接地的金属**（水管/机箱） | 静电击穿是"什么都没做就坏了"的常见原因 |

#### 2. 电源从哪来

| 项 | 值 | 来源 |
| --- | --- | --- |
| 树莓派 5 官方电源要求 | **5V/5A USB-C（官方 27W）** | 官方规格（5A 是为了给 USB 外设留余量） |
| 本基础版的供电方式 | 树莓派 3.3V（物理脚 1 或 17） | 只接一个 DHT11，不需要外部电源 |
| 3.3V 轨电流上限 | 约 **0.5 A（500 mA）** | 40-pin 的 3.3V 由板载稳压器提供 |

**电源不足的典型症状**（不是"跑不起来"，而是"跑得诡异"）：
彩虹屏 / 反复重启 / I2C 器件时有时无 / 传感器读数乱跳。
看到这些先换电源，别急着改代码。

#### 3. 电流预算（本基础版）

| 器件 | 典型电流 | 说明 |
| --- | ---: | --- |
| DHT11 模块 | 0.5~2.5 mA | 只在测量瞬间取电（本基础版唯一的负载） |
| **合计** | **≤ 2.5 mA** | 相对 500 mA 的 3.3V 上限，**可忽略** |

> 以后加器件（LCD、TFT、多个 LED）时，把它们的电流加进来重算；
> 接近 500 mA 就该考虑给器件单独供电（**但地仍要共**）。

#### 4. 电平匹配：什么时候需要电平转换

| 器件输出 | 能否直连树莓派 GPIO | 说明 |
| --- | --- | --- |
| **3.3V 输出**（DHT11 @3.3V 供电、常见的 HC-SR501 模块） | ✅ 可以直连 | 本项目基础版就属于这一类 |
| **5V 输出**（DHT11 误接 5V 时、HC-SR04 的 ECHO） | ❌ **绝对不行** | 必须用 TXS0102 双向电平转换，或用 1kΩ+2kΩ 电阻分压 |
| 开漏输出 + 上拉到 3.3V | ✅ 可以 | 单总线（DHT11）就是这种形态：**上拉接到 3.3V，而不是 5V** |

**记忆点**：决定"能不能直连"的不是器件名字，而是**它的输出电平是多少伏**。
本基础版把 DHT11 接在 3.3V 上，所以数据线是 3.3V —— 这正是必须 3.3V 供电的根本原因。

#### 5. 安全接线检查单（上电前逐条打勾）

- [ ] 电源已**断开**
- [ ] 3.3V ↔ GND 不导通（没有短路）
- [ ] 模块 VCC 接的是**物理脚 1/17**（3.3V），不是脚 2、4（5V）
- [ ] 模块 GND 接的是 **GND 脚**（推荐脚 6）
- [ ] DATA 接的是**物理脚 7（GPIO4）**
- [ ] 裸四针传感器已接 4.7kΩ~10kΩ 上拉到 **3.3V**（不是 5V）
- [ ] 杜邦线插紧、没有跨列（面包板每一列纵向导通）
- [ ] 上电后模块 VCC 对 GND 约 3.3V

#### 6. 出了问题怎么安全收尾

| 情况 | 正确做法 |
| --- | --- |
| 闻到焦味 / 板子发烫 | **立刻拔电源**，不要先看代码 |
| 读数一直不对 | 断电 → 按 `02-接线图.md` 第 5 节重新量一遍 → 再上电 |
| 树莓派起不来 | 断电，拔掉所有杜邦线，只留电源试开机（区分"接线问题"与"系统问题"） |
| 要收工放起来 | `sudo poweroff` → 等绿灯熄灭 → 再拔电源；器件装进塑料盒防潮防静电 |

## 接口接线表（树莓派接线 + 元件接线）

> 这一份**只有两张表**：先看树莓派这头要动哪几个脚，再看元件那头的每个针脚插到哪。
> 供电安全、万用表验证、现象对照见 `02-接线图.md` 与 `03-供电与安全.md`；
> 想接别的器件、看空闲脚见 `01-引脚分配表.md`。

#### 1. 树莓派接线（本基础版要用到的脚）

本基础版只动 **3 个脚**（其余 37 个全空闲）：**脚 1 = 3.3V、脚 6 = GND、脚 7 = DATA**。

| 物理脚 | BCM | 信号 | 接到哪（元件丝印） | 建议线色 | 关键提醒 |
| :---: | --- | --- | --- | :---: | --- |
| **1** | — | 供电 | VCC（元件丝印） | 红 | **必须 3.3V**；不要接 5V（物理脚 2/4）——数据电平会被拉到 5V，伤 GPIO |
| **6** | — | 地 | GND（元件丝印） | 黑 | 任意一个 GND 脚都行（脚 6/9/14/20/25/30/34/39）；**必须共地** |
| **7** | GPIO4 | 数据 | DATA（元件丝印） | 黄 | 单总线数据线（双向）；裸四针传感器必须外接 4.7kΩ~10kΩ 上拉到 3.3V |

> ⚠️ **插线看物理脚号、写代码看 BCM 编号** —— 两者不是偏移关系
> （GPIO4 = 物理脚 7，但 GPIO27 = 物理脚 13）。

#### 2. 元件接线（DHT11 温湿度模块这头）

先认丝印：三针模块通常是 `VCC / DATA / GND`（或 `+ / OUT / -`）；
**裸四针**传感器没有上拉电阻，第 2 行那个 4.7kΩ~10kΩ 电阻必须自己接。

| 元件针脚（丝印） | 信号 | 接到树莓派（物理脚） | BCM | 关键提醒 |
| --- | --- | :---: | --- | --- |
| `VCC` / `+` / `VDD` | **3.3V** | 1/17 | — | **绝不要接 5V**（脚 2/4）：5V 会把数据电平一起拉高，伤 GPIO |
| `DATA` / `OUT` / `S` | **DATA** | 7 | GPIO4 | 单总线（双向）；裸四针必须外接 4.7kΩ~10kΩ 上拉到 3.3V |
| `GND` / `-` | **GND** | 6/9/14/20/25/30/34/39 | — | 任意一个地脚都行（推荐脚 6）；**必须共地** |

> **三根线之外不要多接**：DHT11 没有其它针脚；接错电源（3.3V ↔ 5V）是最常见的烧件原因，
> 接线前请断电（带电插拔是烧 GPIO 的头号原因）。

#### 3. 这一页怎么用

1. **断电**，按第 1 节挑好三个脚（脚 1 / 脚 6 / 脚 7）；

2. 按第 2 节把元件的三个针脚分别插到对应脚（红=3.3V、黑=GND、黄=DATA）；

3. 裸四针传感器：在 DATA 与 3.3V 之间接 4.7kΩ~10kΩ 电阻；

4. 上电后验收：`python3 tools/diag_dht_line.py`（三态电平）→ `python3 run.py`（真实读数 + 动态曲线）。

#### 4. 导出 PDF（打印带上机用）

```bash
node scripts/md2pdf.cjs --in basic/hardware/06-接口接线表.md --out basic/hardware/06-接口接线表.pdf --title "基础版 · 接口接线表（树莓派接线 + 元件接线）"
python3 basic/tools/wire_docs.py --generate     # 让打印清单记住新 PDF 的哈希
```
